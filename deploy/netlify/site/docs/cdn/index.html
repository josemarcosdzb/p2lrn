INSTALACIÓN / CDN

P2LRN por CDN

Esta ruta carga el código de P2LRN en el navegador desde los builds publicados. Player y Studio tienen cargadores distintos. No necesitas instalar esos paquetes mediante NPM en el navegador.

1. Player por CDN

HTML
<script src="https://p2lrn.netlify.app/player/current/dist/p2lrn.js"></script>

<p2lrn-player src="./course.p2lrn"></p2lrn-player>

Para fijar versión:

Player versionado
<script src="https://p2lrn.netlify.app/player/0.5.0-alpha.10/dist/p2lrn.js"></script>

2. Studio visual por CDN

El punto de entrada correcto para HTML sin bundler es el cargador clásico:

HTML mínimo
<script src="https://p2lrn.netlify.app/studio/current/dist/p2lrn-studio.js"></script>

<p2lrn-studio></p2lrn-studio>
El cargador de Studio carga automáticamente el Player del mismo canal.

/studio/current/dist/p2lrn-studio.js carga /player/current/dist/p2lrn.js y después el módulo de Studio. No añadas un segundo cargador del Player.

Versión fija:

Studio versionado
<script src="https://p2lrn.netlify.app/studio/0.5.0-alpha.10/dist/p2lrn-studio.js"></script>

<p2lrn-studio></p2lrn-studio>

3. No uses el ESM directo como sustituto del cargador

p2lrn-studio.esm.js contiene un fallback que importa @p2lrn/player como specifier de paquete. Un HTML puro sin import map no resuelve ese nombre. Por eso la integración CDN documentada usa p2lrn-studio.js, que prepara primero el Player.

4. Studio CDN con un curso existente

HTML
<script src="https://p2lrn.netlify.app/studio/current/dist/p2lrn-studio.js"></script>

<p2lrn-studio src="/course/curso.p2lrn"></p2lrn-studio>

Sin servidor puedes editar y descargar el nuevo .p2lrn.

5. Studio CDN con servidor de la aplicación anfitriona

HTML
<script src="https://p2lrn.netlify.app/studio/current/dist/p2lrn-studio.js"></script>

<p2lrn-studio
  src="/course/curso.p2lrn"
  save-endpoint="/api/p2lrn/studio/save"
  reader-endpoint="/api/p2lrn/studio/read"
  import-endpoint="/api/p2lrn/studio/import"
  course-path="course">
</p2lrn-studio>

CDN resuelve el código del navegador. Los endpoints pertenecen a tu servidor. Si el servidor usa Node puedes implementar esas rutas con @p2lrn/studio/server; en otro stack implementa el mismo contrato HTTP.

Esto no mezcla dos formas de cargar el código en el navegador.

Studio sigue cargándose por CDN. Utilizar un helper NPM sólo en el servidor es independiente de cómo llega el JavaScript al navegador.

6. Qué hace cada endpoint

save-endpoint

Recibe por POST el .p2lrn exportado.

reader-endpoint

Recibe un documento y devuelve estructura para convertirla en contenido.

import-endpoint

Recibe un paquete educativo externo y devuelve un P2LRN convertido.

course-path

Ruta lógica de guardado; el servidor debe sanearla y autorizarla.

7. Sirve todo por HTTP(S)

No abras los ejemplos mediante file://. HTML, paquetes y endpoints deben estar accesibles por HTTP(S) para que fetch, CORS y las políticas del runtime funcionen correctamente.
