BUILD / PACKAGES

Crear paquetes P2LRN

Desde un workspace vacío hasta un .p2lrn validado, incluyendo estructura del paquete, recursos, progresión, documentos y división multipart para payloads grandes.

Qué vas a conseguir

Al terminar podrás crear un curso desde cero, abrir uno existente, añadir recursos, reconstruirlo, validar el resultado y separar un payload grande en partes sin convertir todo el curso en un único archivo pesado.

Workspace + unidades + recursos.

2Construir

Generar un .p2lrn verificable.

3Dividir

Externalizar payloads grandes en .partNNN.

4Reproducir

Abrir el paquete con el Player real.

1. Entender qué hay dentro

Un paquete P2LRN no es simplemente una carpeta comprimida. El manifiesto inventaría los archivos, el grafo describe la estructura educativa y la integridad permite verificar que el contenido sigue siendo el esperado.

course.p2lrn
course.p2lrn
├─ META-INF/
│  └─ manifest.json          # identidad, perfiles, archivos, digests, contentRoot
├─ content/
│  └─ graph.json             # curso, unidades, actividades, recursos y relaciones
├─ assets/
│  └─ ...                    # HTML, vídeo, audio, PDF, imágenes, JSON, etc.
├─ packages/
│  └─ ...                    # payloads externos preservados, si existen
└─ multipart/
   └─ ...                    # descriptores cuando un payload se divide en partes
Importante

El archivo p2lrn.project.json pertenece al workspace de autoría. No tiene que viajar necesariamente como parte de la experiencia final del alumno.

2. Crear un curso completo desde cero

La API pública de autoría es @p2lrn/toolkit/authoring. Este ejemplo crea una unidad, dos recursos HTML, una URL externa, reglas de progresión y finalmente construye el paquete.

create-course.mjs
import {P2LRNAuthoringWorkspace} from '@p2lrn/toolkit/authoring';

const workspace = P2LRNAuthoringWorkspace.create('./workspace', {
  title: 'Curso real de ejemplo P2LRN',
  language: 'es',
  description: 'Curso creado con la API pública de autoría.',
});

workspace.addUnit({
  key: 'unidad-1',
  title: 'Unidad 1 · Fundamentos',
});

workspace.addFile({
  source: './material/intro.html',
  key: 'intro',
  title: 'Introducción',
  parent: 'unidad-1',
  mediaType: 'text/html',
});

workspace.addFile({
  source: './material/practica.html',
  key: 'practica',
  title: 'Práctica',
  parent: 'unidad-1',
  mediaType: 'text/html',
});

workspace.setProgression('act-intro', {
  required: true,
  gateFollowing: true,
  completionRequirement: 'viewed',
});

workspace.setProgression('act-practica', {
  required: true,
  completionRequirement: 'completed',
});

workspace.addUrl({
  url: 'https://p2lrn.netlify.app/docs/',
  key: 'documentacion',
  title: 'Documentación P2LRN',
  parent: 'unidad-1',
});

workspace.build('./curso-ejemplo.p2lrn', {
  strictProfiles: true,
});

El ejemplo ejecutable está incluido en el repositorio en examples/developer-course/create-course.mjs.

3. Leer un documento antes de incorporarlo

workspace.reader() analiza el documento pero no modifica el curso. Esto permite inspeccionar la estructura antes de decidir cómo convertirla en unidades, actividades o recursos.

TypeScript
const document = await workspace.reader(
  './material/tema-1.docx'
);

console.log(document.metadata);
console.log(document.blocks);
console.log(document.tables);
console.log(document.warnings);

Después, tu flujo de autoría decide qué bloques se convierten en unidades, contenido web, cuestionarios o archivos. El Reader no introduce contenido silenciosamente en el grafo.

4. Abrir y modificar un paquete existente

TypeScript
const workspace = P2LRNAuthoringWorkspace.open(
  './curso-ejemplo.p2lrn',
  './workspace-editable'
);

workspace.setCourseMetadata({
  title: 'Curso actualizado',
  incrementRevision: true,
});

workspace.addUnit({
  key: 'unidad-2',
  title: 'Unidad 2',
});

workspace.build('./curso-ejemplo-v2.p2lrn', {
  strictProfiles: true,
});

El flujo open → edit → build conserva identidades portables y está cubierto por las pruebas de round-trip del Toolkit.

5. Validar antes de publicar

Terminal
p2lrn-validate curso-ejemplo.p2lrn
p2lrn-inspect curso-ejemplo.p2lrn
p2lrn-reader curso-ejemplo.p2lrn
  • FORMATEl manifiesto identifica P2LRN y una versión soportada.
  • GRAPHEl grafo y los entrypoints son coherentes.
  • FILESTodos los recursos inventariados existen.
  • HASHLos digests y contentRoot coinciden.
  • PROFILELos perfiles requeridos se validan.

6. Evitar un único paquete enorme: multipart

P2LRN puede dejar el contenedor principal pequeño y sustituir un payload embebido grande por un descriptor multipart. Los bytes grandes se escriben como archivos adyacentes y el Player reconstruye el payload lógico antes de pasarlo al renderer.

ANTES curso.p2lrn manifest + graph + vídeo de 1,4 GB
→
DESPUÉS curso-split.p2lrn manifest + graph + descriptor curso-split.part001 curso-split.part002 curso-split.part003 …
Terminal
p2lrn-multipart   curso.p2lrn   curso-split.p2lrn   --part-size 26214400
Part size por defecto25 MiB · 26214400 bytes
Mínimo admitido1 MiB · 1048576 bytes
Selección automáticapayload embebido más grande que supera el part size
Selección explícita--representation <id>

7. Qué contiene el descriptor multipart

El .p2lrn mantiene dentro un JSON pequeño que describe el payload lógico completo y cada fragmento.

multipart/*.json
{
  "version": "1",
  "mediaType": "video/mp4",
  "size": 1503238553,
  "byteDigest": "sha256:…",
  "parts": [
    {
      "href": "curso-split.part001",
      "size": 26214400,
      "byteDigest": "sha256:…"
    },
    {
      "href": "curso-split.part002",
      "size": 26214400,
      "byteDigest": "sha256:…"
    }
  ]
}

El Player resuelve cada href de forma relativa a la URL del paquete exterior, verifica el SHA-256 de cada parte y vuelve a verificar el digest del payload lógico completo.

8. Cómo publicar un paquete dividido

El contenedor y sus partes deben conservarse juntos en la misma ruta pública relativa.

/courses/curso/
/courses/curso/
├─ curso-split.p2lrn
├─ curso-split.part001
├─ curso-split.part002
├─ curso-split.part003
└─ curso-split.part004
No publiques sólo el .p2lrn exterior

Si falta una parte, si cambia un byte o si una parte se sirve desde otra ruta sin conservar la relación relativa, la reconstrucción falla por integridad o por recurso ausente.

9. Paquetes externos como SCORM

Multipart también preserva vistas package-member. Si una representación apunta a index.html dentro de un ZIP SCORM grande, el descriptor conserva el miembro y el Player reconstruye primero el ZIP lógico antes de resolver ese archivo interno.

10. Si hay varios payloads grandes

El comando multipart actual transforma una representación embebida por ejecución. Puedes seleccionar exactamente cuál con --representation. Mantén bajo control todos los archivos .partNNN producidos y no los separes de su paquete exterior.

Para cursos con muchos vídeos grandes, una alternativa válida es mantener esos medios como recursos remotos autorizados en lugar de incrustarlos todos. La elección depende del contrato de almacenamiento, autorización y portabilidad de tu plataforma.
