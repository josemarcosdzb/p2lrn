Contrato general de actividades

Contrato de datos, ejemplos de código e integración con Player. La creación desde Studio se explica en una guía distinta para profesores.

Los marcadores de huecos admiten {{id}} o ___.

Un mismo cuestionario, distintas experiencias

Las preguntas se guardan como application/vnd.p2lrn.questionnaire+json. La presentación elegida no crea otra copia del contenido: indica al Player cómo debe mostrar ese cuestionario.

La presentación nunca debe perder preguntas.

Si todo el cuestionario no puede representarse fielmente con una mecánica, esa presentación se considera incompatible. P2LRN no elimina preguntas ni inventa respuestas para hacerla encajar.

Estado y puntuación

Todas las presentaciones actualizan el mismo estado del cuestionario. Para escuchar puntuación y finalización utiliza Eventos; para persistirlas en una plataforma, configura Host Adapter.

Probar antes de integrar

El visor permite abrir los paquetes de ejemplo y cambiar de presentación cuando el contenido sea compatible.

Crea y comprueba tus propios ejercicios en Studio. Ya no se publican cursos nativos de prueba.

Guía para crear esta actividad en Studio

Cuestionario estándar

Contrato de datos, ejemplos de código e integración con Player. La creación desde Studio se explica en una guía distinta para profesores.

Requisitos del contenido

  • Admite los tipos de pregunta del cuestionario nativo.
  • Puede utilizar corrección con solución embebida o corrección gestionada por la plataforma.
  • La presentación puede mostrar una pregunta cada vez o todas a la vez.

Ejemplo de datos válido

Este ejemplo recoge los datos de la actividad para quienes trabajan con la CLI. En Studio puedes configurarla desde el editor visual.

quiz.json
{
  "schema": "https://p2lrn.org/schema/native-questionnaire/0.4.0",
  "version": "0.4.0",
  "title": "Comprobación rápida",
  "language": "es",
  "grading": {
    "mode": "embedded-key"
  },
  "presentation": {
    "questionMode": "one-at-a-time",
    "shuffleQuestions": false,
    "showFeedback": "after-submit"
  },
  "questions": [
    {
      "id": "q1",
      "type": "single-choice",
      "prompt": "Capital de Portugal",
      "points": 1,
      "choices": [
        {
          "id": "a",
          "text": "Lisboa"
        },
        {
          "id": "b",
          "text": "Madrid"
        }
      ],
      "solution": {
        "choiceIds": [
          "a"
        ]
      }
    }
  ]
}

Cómo leer el ejemplo

El ejemplo contiene una pregunta de elección única. choices define las opciones y solution.choiceIds identifica la respuesta correcta.

Crear por CLI — alternativa avanzada

Utiliza este recorrido sólo si estás generando el curso por código. Requiere Toolkit instalado mediante NPM. El archivo quiz.json debe contener un cuestionario válido como el ejemplo anterior.

Terminal
p2lrn-create add-questionnaire ./workspace ./quiz.json \
  --key quiz \
  --title "Cuestionario estándar" \
  --renderer "https://p2lrn.org/renderer/questionnaire/standard"

p2lrn-create build ./workspace ./course.p2lrn --strict-profiles

--renderer selecciona la presentación preferida. No crea una segunda copia de las preguntas: el contenido sigue siendo el cuestionario nativo.

Guía para crear esta actividad en Studio

Memoria

Contrato de datos, ejemplos de código e integración con Player. La creación desde Studio se explica en una guía distinta para profesores.

Requisitos del contenido

  • En Studio, el preset de Memoria se edita como una pregunta de tipo Relacionar.
  • La actividad necesita soluciones embebidas y al menos tres parejas.
  • Las pistas y las respuestas no deben repetirse de forma que una pareja resulte ambigua.
Compatibilidad adicional del Player.

El Player también puede convertir otros tipos de pregunta en parejas cuando todas las relaciones se pueden deducir de forma inequívoca. Studio utiliza Relacionar porque es el formato visual más claro para crear este juego.

Ejemplo de datos válido

Este ejemplo recoge los datos de la actividad para quienes trabajan con la CLI. En Studio puedes configurarla desde el editor visual.

quiz.json
{
  "schema": "https://p2lrn.org/schema/native-questionnaire/0.4.0",
  "version": "0.4.0",
  "title": "Relacionar países y capitales",
  "language": "es",
  "grading": {
    "mode": "embedded-key"
  },
  "questions": [
    {
      "id": "q1",
      "type": "matching",
      "prompt": "Relaciona cada país con su capital",
      "points": 3,
      "left": [
        {
          "id": "l1",
          "text": "España"
        },
        {
          "id": "l2",
          "text": "Francia"
        },
        {
          "id": "l3",
          "text": "Italia"
        }
      ],
      "right": [
        {
          "id": "r1",
          "text": "Madrid"
        },
        {
          "id": "r2",
          "text": "París"
        },
        {
          "id": "r3",
          "text": "Roma"
        }
      ],
      "solution": {
        "pairs": [
          {
            "left": "l1",
            "right": "r1"
          },
          {
            "left": "l2",
            "right": "r2"
          },
          {
            "left": "l3",
            "right": "r3"
          }
        ]
      }
    }
  ]
}

Cómo leer el ejemplo

El ejemplo usa una pregunta matching con tres elementos a cada lado. solution.pairs declara las tres relaciones y permite construir las seis cartas.

Guía para crear esta actividad en Studio

Clasificar

Requisitos técnicos, ejemplos de datos e integración del renderizador. La creación desde Studio se explica en la guía del profesor.

Requisitos del contenido

  • En Studio se crea como una pregunta de tipo Clasificar.
  • Cada pregunta necesita al menos dos objetos y dos categorías.
  • La solución debe asignar todos los objetos a una categoría válida.
  • La actividad requiere soluciones embebidas.

Ejemplo de datos válido

Este ejemplo recoge los datos de la actividad para quienes trabajan con la CLI. En Studio puedes configurarla desde el editor visual.

quiz.json
{
  "schema": "https://p2lrn.org/schema/native-questionnaire/0.4.0",
  "version": "0.4.0",
  "title": "Clasificar seres vivos",
  "language": "es",
  "grading": {
    "mode": "embedded-key"
  },
  "questions": [
    {
      "id": "q1",
      "type": "classification",
      "prompt": "Clasifica cada elemento",
      "points": 2,
      "items": [
        {
          "id": "perro",
          "text": "Perro"
        },
        {
          "id": "roble",
          "text": "Roble"
        }
      ],
      "categories": [
        {
          "id": "animal",
          "text": "Animal"
        },
        {
          "id": "planta",
          "text": "Planta"
        }
      ],
      "solution": {
        "assignments": [
          {
            "item": "perro",
            "category": "animal"
          },
          {
            "item": "roble",
            "category": "planta"
          }
        ]
      }
    }
  ]
}

Cómo leer el ejemplo

items son los objetos, categories son los destinos y solution.assignments contiene una asignación por objeto.

Verdadero o falso

Requisitos técnicos, ejemplos de datos e integración del renderizador. La creación desde Studio se explica en la guía del profesor.

Requisitos del contenido

  • En Studio se crea con preguntas de tipo Verdadero / Falso.
  • Se necesitan al menos dos preguntas.
  • Cada pregunta debe tener exactamente dos opciones inequívocas y una solución embebida.

Ejemplo de datos válido

Este ejemplo recoge los datos de la actividad para quienes trabajan con la CLI. En Studio puedes configurarla desde el editor visual.

quiz.json
{
  "schema": "https://p2lrn.org/schema/native-questionnaire/0.4.0",
  "version": "0.4.0",
  "title": "Verdadero o falso",
  "language": "es",
  "grading": {
    "mode": "embedded-key"
  },
  "questions": [
    {
      "id": "q1",
      "type": "true-false",
      "prompt": "La Tierra orbita alrededor del Sol",
      "points": 1,
      "choices": [
        {
          "id": "t1",
          "text": "Verdadero"
        },
        {
          "id": "f1",
          "text": "Falso"
        }
      ],
      "solution": {
        "choiceIds": [
          "t1"
        ]
      }
    },
    {
      "id": "q2",
      "type": "true-false",
      "prompt": "Marte es una estrella",
      "points": 1,
      "choices": [
        {
          "id": "t2",
          "text": "Verdadero"
        },
        {
          "id": "f2",
          "text": "Falso"
        }
      ],
      "solution": {
        "choiceIds": [
          "f2"
        ]
      }
    }
  ]
}

Cómo leer el ejemplo

Cada pregunta tiene dos choices. La solución señala cuál de sus identificadores es correcto mediante solution.choiceIds.

Sopa de letras

Requisitos técnicos, ejemplos de datos e integración del renderizador. La creación desde Studio se explica en la guía del profesor.

Requisitos del contenido

  • En Studio se edita con preguntas de tipo Respuesta de texto.
  • Se necesitan al menos tres respuestas.
  • Cada respuesta normalizada debe tener entre 3 y 16 caracteres.
  • Todas las palabras deben poder colocarse: P2LRN no elimina preguntas para forzar el tablero.

Ejemplo de datos válido

Este ejemplo recoge los datos de la actividad para quienes trabajan con la CLI. En Studio puedes configurarla desde el editor visual.

  "version": "0.4.0",
  "title": "Planetas",
  "language": "es",
  "grading": {
    "mode": "embedded-key"
  },
  "questions": [
    {
      "id": "q1",
      "type": "text",
      "prompt": "Planeta más cercano al Sol",
      "points": 1,
      "solution": {
        "acceptedAnswers": [
          "MERCURIO"
        ]
      }
    },
    {
      "id": "q2",
      "type": "text",
      "prompt": "Segundo planeta del Sistema Solar",
      "points": 1,
      "solution": {
        "acceptedAnswers": [
          "VENUS"
        ]
      }
    },
    {
      "id": "q3",
      "type": "text",
      "prompt": "Nuestro planeta",
      "points": 1,
      "solution": {
        "acceptedAnswers": [
          "TIERRA"
        ]
      }
    }
  ]
}

Cómo leer el ejemplo

Cada pregunta textual aporta una pista y una respuesta aceptada. El Player normaliza las respuestas y construye la cuadrícula sólo si puede representar el conjunto completo.

Crucigrama

Requisitos técnicos, ejemplos de datos e integración del renderizador. La creación desde Studio se explica en la guía del profesor.

Requisitos del contenido

  • En Studio se edita con preguntas de tipo Respuesta de texto.
  • Necesita entre 4 y 80 respuestas.
  • Cada respuesta normalizada debe tener entre 3 y 17 caracteres y una pista no vacía.
  • Todas las palabras deben formar un único crucigrama conectado. Si no existe una disposición completa, la presentación se rechaza.

    {
      "id": "q1",
      "type": "text",
      "prompt": "Lugar donde se vive",
      "points": 1,
      "solution": {
        "acceptedAnswers": [
          "CASA"
        ]
      }
    },
    {
      "id": "q2",
      "type": "text",
      "prompt": "Anfibio que salta",

Guía de creación para profesores

Rosco

Requisitos técnicos, ejemplos de datos e integración del renderizador. La creación desde Studio se explica en la guía del profesor.

Requisitos del contenido

  • En Studio se edita con preguntas de tipo Respuesta de texto.
  • Cada pregunta necesita exactamente una respuesta textual utilizable.
  • La respuesta debe tener al menos dos caracteres normalizados.
  • Cada reto necesita una letra distinta que esté presente en su propia respuesta. P2LRN no inventa respuestas ni elimina preguntas.

Ejemplo de datos válido

Este ejemplo recoge los datos de la actividad para quienes trabajan con la CLI. En Studio puedes configurarla desde el editor visual.

quiz.json
{
  "schema": "https://p2lrn.org/schema/native-questionnaire/0.4.0",
  "version": "0.4.0",
  "title": "Rosco de vocabulario",
  "language": "es",
  "grading": {
    "mode": "embedded-key"
  },
  "questions": [
    {
      "id": "q1",
      "type": "text",
      "prompt": "Vivienda",
      "points": 1,
      "solution": {
        "acceptedAnswers": [
          "CASA"
        ]
      }
    },
    {
      "id": "q2",
      "type": "text",
      "prompt": "Animal doméstico que ladra",
      "points": 1,
      "solution": {
        "acceptedAnswers": [
          "PERRO"
        ]
      }
    },
    {
      "id": "q3",
      "type": "text",
      "prompt": "Mueble para comer o trabajar",
      "points": 1,
      "solution": {
        "acceptedAnswers": [
          "MESA"
        ]
      }
    },
    {
      "id": "q4",
      "type": "text",
      "prompt": "Satélite natural de la Tierra",
      "points": 1,
      "solution": {
        "acceptedAnswers": [
          "LUNA"
        ]
      }
    }
  ]
}

Cómo leer el ejemplo

CASA, PERRO, MESA y LUNA permiten asignar, por ejemplo, C, P, M y L. El Player calcula esa asociación a partir de las respuestas reales; este bloque sí es un cuestionario válido, no una lista de comentarios.

Crear por CLI — alternativa avanzada

Utiliza este recorrido sólo si estás generando el curso por código. Requiere Toolkit instalado mediante NPM. El archivo quiz.json debe contener un cuestionario válido como el ejemplo anterior.

Terminal
p2lrn-create add-questionnaire ./workspace ./quiz.json \
  --key quiz \
  --title "Rosco" \
  --renderer "https://p2lrn.org/renderer/questionnaire/rosco"

p2lrn-create build ./workspace ./course.p2lrn --strict-profiles

--renderer selecciona la presentación preferida. No crea una segunda copia de las preguntas: el contenido sigue siendo el cuestionario nativo.

Juego 3D

Requisitos técnicos, ejemplos de datos e integración del renderizador. La creación desde Studio se explica en la guía del profesor.

Requisitos del contenido

  • El preset de Studio crea una pregunta de tipo Ordenar con solución completa.
  • La actividad requiere soluciones embebidas y textos distinguibles.
  • El Player también puede reproducir actividades 3D de tipo Relacionar y Clasificar cuando se generan mediante Toolkit y cumplen sus contratos completos.
  • Si las físicas no pueden iniciarse, la experiencia conserva una alternativa funcional.

Ejemplo de datos válido

Este ejemplo recoge los datos de la actividad para quienes trabajan con la CLI. En Studio puedes configurarla desde el editor visual.

quiz.json
{
  "schema": "https://p2lrn.org/schema/native-questionnaire/0.4.0",
  "version": "0.4.0",
  "title": "Ordenar el ciclo del agua",
  "language": "es",
  "grading": {
    "mode": "embedded-key"
  },
  "questions": [
    {
      "id": "q1",
      "type": "ordering",
      "prompt": "Ordena las fases",
      "points": 3,
      "items": [
        {
          "id": "i1",
          "text": "Evaporación"
        },
        {
          "id": "i2",
          "text": "Condensación"
        },
        {
          "id": "i3",
          "text": "Precipitación"
        }
      ],
      "solution": {
        "order": [
          "i1",
          "i2",
          "i3"
        ]
      }
    }
  ]
}

Cómo leer el ejemplo

El ejemplo utiliza ordenar porque es el recorrido que Studio ofrece actualmente para crear un Juego 3D. Los tres elementos y solution.order producen una prueba completa.
