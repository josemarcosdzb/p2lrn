INTEGRACIÓN / EVENTOS

Eventos del Player

Los eventos p2lrn:* permiten observar qué ocurre durante la carga y la reproducción. Sirven para actualizar la interfaz de tu aplicación, registrar telemetría y coordinar el estado con Host Adapter.

1. Escuchar eventos

JavaScript
const player = document.querySelector('p2lrn-player');

for (const type of [
  'p2lrn:ready',
  'p2lrn:rendered',
  'p2lrn:score',
  'p2lrn:statechange',
  'p2lrn:complete',
  'p2lrn:progressionchange',
  'p2lrn:error',
]) {
  player.addEventListener(type, (event) => {
    console.log(type, event.detail);
  });
}

Escucha los eventos sobre el elemento Player. El dato útil de cada notificación se encuentra en event.detail.

2. Ciclo habitual de reproducción

  1. p2lrn:readyEl paquete se ha cargado y el Player está preparado.
  2. p2lrn:renderedLa presentación seleccionada se ha representado para una entidad.
  3. p2lrn:statechange / p2lrn:scoreLa actividad informa de cambios de respuesta, estado o puntuación cuando procede.
  4. p2lrn:completeLa actividad comunica que ha finalizado.
  5. p2lrn:progressionchangeEl Player informa de un cambio en las reglas de progresión calculadas.

No todas las actividades producen todos los eventos intermedios. El ciclo depende del tipo de contenido y de la interacción del alumno.

3. Referencia de eventos

p2lrn:ready

Paquete cargado. Incluye identificadores del paquete y su raíz de contenido.

p2lrn:rendered

Una entidad ha sido presentada por un renderizador.

p2lrn:score

Una actividad ha producido una puntuación.

p2lrn:statechange

Ha cambiado el estado de una actividad compatible.

p2lrn:complete

Una actividad ha comunicado su finalización.

p2lrn:progressionchange

Ha cambiado el estado de navegación o progresión calculado por el Player.

p2lrn:error

Se ha producido un error estructurado durante carga, representación, progresión o integración.

4. Qué contiene event.detail

El detalle incluye el dato específico del evento y el contexto necesario para relacionarlo con el paquete, la entidad o la actividad correspondiente. Trata event.detail como el contrato del evento; no extraigas información de textos visibles de la interfaz.

5. Eventos y Host Adapter

Cuando hay un Host Adapter configurado, el Player también puede reenviar los eventos mediante emitEvent(). Esto permite que una aplicación centralice registro, analítica o sincronización sin tener que duplicar listeners para cada pantalla.

6. Tratar errores

p2lrn:error incluye una fase que ayuda a localizar el origen. Entre las fases utilizadas están carga del paquete, representación, carga o guardado de progresión y envío de eventos al Host Adapter. Muestra al usuario un mensaje comprensible y conserva el detalle técnico para diagnóstico.

7. Nombres que debes utilizar

Usa únicamente los eventos publicados.

Para estado utiliza p2lrn:statechange; para finalización, p2lrn:complete; para cambios de progresión, p2lrn:progressionchange. Evita nombres históricos o inventados porque no forman parte del contrato actual.
