Empieza sin mezclar NPM, CDN y Studio

Antes de copiar código hay que separar dos decisiones distintas: cómo cargas P2LRN en tu aplicación y cómo creas el curso. NPM y CDN son canales alternativos de distribución. Studio y Toolkit son formas de autoría.

1. Elige cómo cargar el Player

PROYECTO CON BUILD

NPM

Instalas @p2lrn/player en tu proyecto y lo importas desde JavaScript/TypeScript. En esta ruta no se usa el script del CDN.

 HTML DIRECTO

CDN

Cargas el Player con una etiqueta <script>. En esta ruta no necesitas npm install @p2lrn/player.
NPM y CDN no son pasos consecutivos.

Son dos formas alternativas de cargar el mismo Player. Si eliges NPM, importa el paquete. Si eliges CDN, usa la URL del CDN. No hagas ambas cosas en el mismo ejemplo.

2. Elige cómo crear el curso

SIN PROGRAMAR

Studio visual

Crea o abre un curso, añade unidades, lecciones, archivos, documentos, cuestionarios y juegos desde el editor visual; después previsualiza y exporta el .p2lrn.

 POR CÓDIGO

Toolkit / CLI

Crea y transforma paquetes desde Node/TypeScript o comandos. Es la ruta adecuada para automatización, pipelines y generación programática.

3. Qué combinación corresponde a cada caso

Studio + CDN

Creas visualmente un .p2lrn y lo reproduces en una página sin instalar el Player por NPM.

Studio + NPM

Creas visualmente el paquete y lo reproduces dentro de una aplicación que integra @p2lrn/player por NPM.

Toolkit + NPM

Generas o validas cursos por código y usas el Player como dependencia de tu aplicación.

Toolkit + CDN

Generas el paquete con herramientas Node, pero la página que lo reproduce carga el Player directamente desde CDN.

La creación del paquete y la forma de cargar el Player son decisiones independientes. Lo que se evita es mezclar NPM y CDN para cargar el Player dentro del mismo camino.
