¿Vas a crear un curso como profesor?

No necesitas elegir servicios del Host ni escribir código. Empieza en tu primer curso con Studio. Esta referencia es para la integración técnica.

DESARROLLADORES / COMPONENTES

Mapa de componentes

Esta referencia explica qué corresponde al archivo del curso, al editor, al reproductor y a los servicios de una plataforma educativa. Está destinada a quienes integran P2LRN en una aplicación.

1. El recorrido completo

Studio o Toolkit→.p2lrn→Player↕Host Adapter / Capability Broker↕tu plataforma

Studio y Toolkit producen o modifican el paquete. Player lo reproduce. Host Adapter comunica estado, puntuación, eventos y recursos; Capability Broker conecta servicios vivos opcionales como colaboración sin introducir endpoints ni credenciales en el curso.

2. Componentes principales

Studio

Editor visual para cursos, imágenes, cuestionarios, juegos, colaboración, recursos compartidos y grupos de actividades.

Componentes nativos

Contenido portable sin dependencias externas, incluidos texto, imagen, vídeo, Aviso, pestañas y línea temporal.

Toolkit

Autoría/Reader/validación/conversión, Host de referencia y CLI.

Player

Abre y verifica el paquete, negocia capacidades y reproduce representaciones.

Host Adapter

Estado, puntuación, eventos y recursos protegidos.

Capability Broker

Servicios vivos opcionales como colaboración/IA sin entregar secretos al curso.

Offline Host Adapter

Estado local y outbox ordenado; puede sincronizar al volver la red.

Package Cache

Conserva bytes verificados del curso para reabrirlos offline. No contiene estado del alumno.

Resource Library

Biblioteca de recursos compartidos identificados y comprobados mediante su huella SHA-256.

Host con autoridad sobre los datos

Servicio del servidor que comprueba identidad, permisos y calificaciones oficiales; no confía en los datos enviados por el navegador.

Reader

Extrae estructura de documentos para decidir cómo convertirla a contenido.

Multipart

Transporte verificado de recursos grandes fuera del archivo principal.

3. Qué componente usar según la tarea

Un profesor crea un curso

Studio.

Un proceso genera muchos cursos

Toolkit y CLI.

Una web reproduce el curso

Player.

Guardar progreso o notas oficiales

Host Adapter y backend autorizado; usa el Host autoritativo de referencia como patrón, no como sistema de identidad.

Seguir trabajando sin red

Offline Host Adapter para estado/outbox y Package Cache para bytes del curso.

Reutilizar recursos entre cursos

Biblioteca compartida o recurso remoto cuya huella se comprueba antes de utilizarlo.

Dos alumnos colaboran

Capability Broker + provider de colaboración del Host.

Integrar en un LMS

Integración de Player con un servidor autorizado o proveedor LTI 1.3 instalado en tu infraestructura.

Importar un documento

Reader.

Recurso muy grande

Multipart.

4. Qué no debe guardarse dentro del paquete

El paquete contiene estructura, contenido, perfiles y metadatos portables. No debe convertirse en una base de datos de usuarios. Identidad, contraseñas, permisos, matrículas, secretos, progreso individual y datos privados permanecen en la plataforma.

5. Cómo encaja la instalación

NPM y CDN son formas de cargar componentes del navegador; no son productos distintos. Una vez elegido el recorrido de instalación, la API del Player o de Studio es la misma para esa versión.
