CREAR / ENTREGA SIN LMS

Entrega offline y paquetes autorreproducibles

Convierte un curso .p2lrn en una entrega que el alumno puede abrir sin LMS, completar en el navegador y devolver como .p2lrn-result. El curso sigue siendo el mismo paquete P2LRN: la entrega offline añade alrededor el Player, el runtime y la política del intento.

1. Qué significa «autorreproducible»

Una entrega autorreproducible —también llamada de forma informal «autoejecutable»— lleva lo necesario para abrir el curso sin instalar P2LRN ni matricular al alumno en un LMS. El navegador continúa siendo la interfaz de reproducción.

.p2lrn

Es el curso portable y canónico: contenido, estructura, recursos y actividades.

Entrega offline

Es el envoltorio de distribución que añade el Player/runtime, la configuración del intento y un lanzador local.

.p2lrn-result

Es el archivo que genera el alumno al terminar y que el profesor vuelve a abrir en Studio para revisar la entrega.

No es un nuevo formato de curso ni un .exe.

El archivo Windows actual es un lanzador .p2lrn-offline.cmd. Al abrirlo inicia el entorno local de la entrega y abre el curso en el navegador. El .p2lrn interno conserva su identidad y puede seguir utilizándose normalmente en Player, LMS o web.

2. Los dos formatos actuales

FormatoQué recibe el alumnoCómo se abreCuándo elegirlo
Windows · un archivoUn .p2lrn-offline.cmd con la entrega incorporada.Doble clic. El lanzador prepara el contenido verificado y abre una dirección local 127.0.0.1 en el navegador.Es la opción más sencilla cuando el alumno utiliza Windows.

«Portable» describe el paquete de entrega, no una promesa de compatibilidad con todos los sistemas operativos. El lanzador distribuido actualmente dentro de estas entregas es el de Windows.

4. Generar la entrega en Studio

Abre el curso en P2LRN Studio, comprueba primero la Vista alumno y después pulsa Entrega offline. No se crea otro curso: Studio empaqueta el .p2lrn actual junto con el runtime de la entrega.

La opción Firmar el encargo es voluntaria. Al elegirla se generan dos descargas diferentes: la entrega destinada al alumno y el comprobante .p2lrn-assignment.json que conservará el profesor. Sin marcarla, la entrega funciona como antes.

Formato

Windows de un archivo o ZIP portable.

Alumno

Identificador opcional que puede quedar asociado a la entrega.

Disponibilidad y fecha límite

Permiten indicar cuándo debe realizarse la actividad; estando completamente offline dependen del reloj del equipo del alumno.

Duración e intentos

Puedes fijar tiempo máximo por intento, número de intentos y si se permite reanudar.

Métricas

La opción de actividad registra eventos y tiempo activo para incluirlos en el resultado.

Firma opcional

Firma el encargo y prepara un comprobante para revisar la devolución. No firma el programa Windows ni las respuestas del alumno.

5. Qué hace el alumno

  1. Recibe la entrega.Puede llegar por correo, almacenamiento compartido, USB u otro canal elegido por el profesor.
  2. La abre.En Windows de un archivo, hace doble clic en el .cmd. En ZIP, extrae primero y abre el lanzador incluido.
  3. Trabaja en el navegador.El lanzador sirve temporalmente el curso desde el propio equipo; no necesita un LMS ni una sesión de alumno en una plataforma.
  4. Finaliza.La entrega genera el resultado y el navegador descarga el archivo .p2lrn-result.
  5. Lo devuelve.Envía ese único archivo al profesor. El alumno no tiene que editar el JSON ni volver a empaquetar el curso.

6. Qué contiene el .p2lrn-result

El resultado está separado del curso. Según la actividad y la configuración, puede recoger respuestas, puntuaciones, eventos de ejecución, información del intento y métricas como el tiempo activo. Studio verifica además que el resultado corresponda al curso y a la entrega esperados.

El profesor no necesita abrir archivos internos a mano.

En Studio pulsa Revisar entrega, selecciona el .p2lrn-result y consulta la información de la entrega desde la interfaz.

7. Revisar la devolución en Studio

  1. Abre el curso original en Studio. La devolución debe corresponder a ese curso.
  2. Pulsa Revisar entrega y selecciona el .p2lrn-result del alumno.
  3. Si se generó una entrega firmada, selecciona también el comprobante que conservó el profesor. La firma incluida en el resultado, por sí sola, no demuestra quién emitió el encargo.
  4. Revisa las comprobaciones separadas: SHA-256 del archivo, curso original, firma y comprobante, cadena de registros y coherencia entre respuestas, notas y resumen.
  5. Consulta las respuestas, la puntuación declarada, los eventos y las posibles incidencias. Si alguna comprobación falla, no trates la puntuación como una calificación acreditada.

Las entregas antiguas siguen pudiendo abrirse. Si no conservaron el orden original de eventos y puntuaciones, la cadena se presenta como no verificable, no como una manipulación confirmada.

Importante: una firma Ed25519 válida cotejada con el comprobante confirma el encargo del profesor. No autentica que las respuestas, la identidad o el tiempo del alumno sean fiables en un ordenador bajo su control.

9. Seguridad de las entregas

Para prácticas normales basta con la entrega offline. Para una evaluación puedes activar «Firmar el encargo» en Studio. Así se firma con Ed25519 la identidad del curso y las condiciones establecidas por el profesor.

  1. Genera la entrega activando «Firmar el encargo». Descarga el archivo para el alumno y después el .p2lrn-assignment.json que Studio ofrece por separado.
  2. Conserva el comprobante en tu ordenador; no lo utilices como archivo a devolver por el alumno. La clave privada de firma no se exporta.
  3. El alumno realiza el curso sin conexión y devuelve el archivo .p2lrn-result habitual.
  4. Abre el curso original en Studio, elige «Revisar entrega», selecciona el resultado y después el comprobante original. Studio coteja la firma y la identidad del encargo, y revisa por separado los registros y el resumen.
Qué aporta

Permite cotejar el encargo con el comprobante que conservó el profesor y localizar incoherencias en los datos declarados. Conserva el orden original de eventos, estados y puntuaciones para evitar falsas alertas.

Qué no aporta

El alumno puede recalcular los hashes de su resultado. La firma no protege sus respuestas ni convierte las puntuaciones locales en notas oficiales. Algunos juegos conservan soluciones para ofrecer corrección inmediata.

Ejecutable Windows

El lanzador actual sigue siendo un .cmd y no está firmado digitalmente; no existe un .exe firmado. No es un programa de examen bloqueado ni acredita identidad o tiempo absoluto.

Para exámenes oficiales o de alto riesgo se requiere un equipo supervisado o controles externos de identidad y tiempo. La firma del encargo es una mejora concreta para evaluaciones habituales, no una protección antifraude absoluta.

10. Elegir entre paquete normal y entrega offline

PAQUETE NORMAL

.p2lrn

Elígelo para Player, una web, una aplicación o integración LMS. Es el formato portable del curso.

SIN LMS

Entrega autorreproducible

Elígela cuando el alumno necesite recibir, abrir y devolver la actividad como archivo sin depender de una plataforma.

11. Problemas frecuentes

No se puede generar la entrega

Comprueba que el curso es autocontenido y que su Player está disponible. Si aparece «El runtime Player cambió durante la exportación», el archivo recibido no coincide con el manifiesto: no desactives la comprobación de integridad. Actualiza Studio y vuelve a intentarlo; si persiste, comunica la ruta del recurso indicada en el error.

No se puede firmar

Para usar Ed25519 necesitas un navegador actualizado compatible. También puedes crear una entrega normal para actividades ordinarias; no se firmarán sus condiciones.

Falta el comprobante del profesor

La firma incluida en el archivo devuelto no acredita por sí sola quién creó el encargo. Conserva el .p2lrn-assignment.json descargado al exportar: si se pierde, no podrás comparar el resultado con esa copia original.

La cadena aparece como «no verificable»

Las entregas antiguas que no conservaron el orden de estados, eventos y puntuaciones pueden carecer de información suficiente para reconstruir la secuencia. Eso no demuestra una manipulación.

Windows bloquea el lanzador

El archivo .cmd no tiene firma digital de editor. Comprueba su procedencia y consulta las políticas de seguridad del centro; no desactives las protecciones del sistema para ejecutarlo.
