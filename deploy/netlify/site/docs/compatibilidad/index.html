Compatibilidad y migración

No todas las capacidades significan lo mismo. Esta tabla separa lo que P2LRN puede crear, abrir, leer, conservar y reproducir para evitar prometer una migración más completa de lo que realmente permite cada formato.

1. Qué significa cada columna

Nativo

El formato forma parte del modelo propio de P2LRN.

Crear

Toolkit puede producir ese contenido de forma nativa.

Abrir y reconstruir

Un paquete que contiene ese perfil puede abrirse como proyecto y volver a construirse sin perder el artefacto declarado.

Leer

Reader puede interpretar estructura o contenido útil de ese formato.

Conservar

P2LRN puede transportar el artefacto aunque no pueda editarlo o reproducirlo completamente.

Reproducir

El Toolkit declara una ruta completa de entrega para ese perfil.

«Conservar» no significa «editar» ni «reproducir».

Por ejemplo, un paquete externo puede viajar intacto dentro de P2LRN aunque su edición siga perteneciendo a otra herramienta.

3. Cómo evaluar una migración

  1. Comprueba la columna que necesitas.Si quieres editar, «Conservar: sí» no es suficiente; necesitas una ruta de creación o reconstrucción adecuada.
  2. Prueba el paquete resultante.Abre una muestra real con el visor y comprueba recursos, navegación y eventos.
  3. Verifica contenido ejecutable.SCORM, H5P, cmi5 y otros paquetes pueden necesitar un entorno de ejecución aislado y recursos adicionales.
  4. No des por hecho equivalencia semántica.Que un archivo pueda leerse o transportarse no significa que todas las reglas del LMS de origen puedan convertirse automáticamente.

4. Formatos externos y Player

El Player dispone de infraestructura para ejecutar varios formatos externos, pero la capacidad final depende de que el paquete incluya una representación compatible y de que el entorno de ejecución necesario esté disponible. Por eso la matriz anterior no convierte automáticamente «Leer» o «Conservar» en «Reproducir».

Para una integración concreta, prepara un paquete de prueba, ábrelo con el Player y valida el recorrido completo antes de migrar contenido en volumen.

5. Paquetes P2RLN Alpha15

P2RLN Alpha15 es una identidad histórica anterior a P2LRN. Si recibes uno de esos paquetes, puedes reempaquetarlo con los identificadores actuales antes de continuar trabajando con él.

Terminal
p2lrn-repack old-course.p2rln new-course.p2lrn --canonicalize-identifiers

Después de convertirlo, valida el nuevo paquete y pruébalo con Player antes de sustituir el original.

Reproducción activa comprobada

El Player crea por defecto un sandbox de origen opaco para SCORM, H5P y los lanzamientos HTML locales compatibles de otros paquetes. No hace falta programar otro runtime en la aplicación integradora. La comunicación usa un canal privado y el estado se guarda fuera del contenido mediante Host Adapter.

  • SCORM 1.2: paquete interactivo del repositorio completado con 100/100 en Chromium. SCORM 2004: API y persistencia verificadas con una actividad sintética; no es certificación completa.
  • H5P Crossword real: reproducción y evento xAPI al comprobar respuestas, con librerías adicionales del catálogo distribuido. Persistencia e aislamiento se verifican además con una actividad sintética.
  • HTML genérico y cmi5: aislamiento verificado con actividades sintéticas. cmi5 dispone de estado y declaraciones de previsualización; no equivale a una sesión de producción en un LMS/LRS.
  • Las librerías H5P ausentes, servicios externos, código de servidor y Flash siguen siendo dependencias o restricciones explícitas. La carga dinámica y los marcos internos pueden necesitar un origen HTTP administrado.

Las pruebas actuales se han ejecutado en Chromium. No se declara compatibilidad universal con todos los paquetes ni con Firefox y Safari. La política CSP de la aplicación y las restricciones del navegador pueden impedir la ejecución.
