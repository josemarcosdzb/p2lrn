INTEGRATE

Integración real

Cómo pasar de un archivo .p2lrn aislado a una integración completa con frontend, backend, eventos, progreso, CORS y runtimes externos.

Arquitectura de referencia

.p2lrn→servidor/CDN→aplicación→Player→eventos→persistencia host

Opción A · HTML estático + CDN

Úsala cuando sólo necesitas reproducir un paquete público y no quieres añadir dependencias npm.

HTML
<script src="https://p2lrn.netlify.app/player/current/dist/p2lrn.js"></script>
<p2lrn-player src="https://content.example.com/course.p2lrn"></p2lrn-player>

Opción B · npm + bundler

Terminal
npm install @p2lrn/player
JavaScript
import '@p2lrn/player';

Backend y Host Adapter

El host debe encargarse de autenticación, permisos, matrícula, persistencia durable y resolución de URLs protegidas. El Player comunica actividad mediante su contrato de eventos/adapter, pero no sustituye esa lógica.

Contenido en otro origen

Configura CORS en el servidor de contenido. No abras CORS de forma indiscriminada si el material es privado: genera URLs autorizadas desde el backend y limita el origen cuando corresponda.

H5P y SCORM

Cuando el paquete referencia contenido que requiere ejecución especializada, el Player usa hosts de runtime aislados. Las librerías H5P compartidas pueden distribuirse aparte para reducir duplicación.

Criterio de salida

  • PACKAGEEl paquete abre y verifica.
  • PLAYEREl Player emite ready/rendered sin errores.
  • EVENTSLa aplicación recibe progreso/estado cuando corresponde.
  • HOSTLa persistencia y autorización funcionan fuera del paquete.
  • RUNTIMEH5P/SCORM sólo se anuncian como ejecutables si el runtime responde.
