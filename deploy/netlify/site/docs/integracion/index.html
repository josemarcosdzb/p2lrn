Integración real

El Player se ocupa del paquete y del runtime. Tu aplicación host se ocupa del usuario, autorización, progreso durable, secretos y backend.

Terminal + JS

C · Host Adapter

JavaScript
const adapter = P2LRN.createHostAdapter({
  async loadState(context) {
    return loadProgressFromYourBackend(context);
  },
  async saveState(state, context) {
    await saveProgressToYourBackend(state, context);
  },
  async reportScore(score, context) {
    await reportScoreToYourBackend(score, context);
  },
  async emitEvent(event, context) {
    auditRuntimeEvent(event, context);
  },
  async resolveResourceUrl(request, context) {
    const url = await getAuthorizedResourceUrl(request, context);
    return url ? {url, verified: true, seekable: request.seekable === true} : null;
  },
});

const player = document.querySelector('p2lrn-player');
player.adapter = adapter;
No copies estos nombres como endpoints.

loadProgressFromYourBackend y similares representan funciones de tu aplicación. P2LRN no prescribe rutas HTTP para tu backend.

D · Contenido privado

La identidad del alumno y los secretos no pertenecen al paquete. Tu backend autentica al usuario y entrega una URL autorizada o resuelve el recurso mediante el Host Adapter. El Player exige verified:true para aceptar una URL resuelta por el host.

E · Runtimes externos

runtime-base-url permite apuntar a un host controlado. Para H5P, SCORM, cmi5 y otros paquetes ejecutables, ese host debe usar un origen distinto al de la aplicación que embebe el Player. Separar sólo por ruta no aísla el contenido.

HTML
<p2lrn-player
  src="https://content.example.com/course.p2lrn"
  runtime-base-url="https://runtime.example.net/p2lrn/runtime-host/">
</p2lrn-player>

El visor público de P2LRN usa un segundo origen Netlify para el runtime y comprueba que la versión del host coincida con la del Player antes de reproducir. La existencia del runtime no implica autoría nativa ni round-trip completo.

Persistencia de progresión

Cuando el perfil progression está activo, el Player puede cargar estado con loadState, actualizarlo a partir de rendered, score, statechange y complete, y guardarlo mediante saveState.

CORS

Si el paquete está en otro origen, el servidor debe permitir la solicitud del navegador. CORS no sustituye autorización. Para material privado, usa una política de origen explícita y autorización real en backend.

Criterio de salida

  • PACKAGEManifest, graph y payloads verifican.
  • PLAYERready y rendered llegan sin error.
  • HOSTEstado y score se persisten fuera del paquete.
  • PRIVATEEl paquete no contiene credenciales ni identidad del alumno.
  • RUNTIMELos runtimes anunciados responden realmente.
