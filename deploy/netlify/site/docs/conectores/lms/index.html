CONECTORES / LMS

Conectores con plataformas LMS

P2LRN está diseñado para mostrar los mismos cursos y actividades en LMS diferentes. Existen el Player y el Host Adapter comunes; el gateway LTI 1.3 multiinstitución continúa en desarrollo y no debe confundirse con una integración terminada.

Qué solución necesita tu plataforma

Player integrado directamente

Tu web carga <p2lrn-player> por NPM o CDN y usa un Host Adapter para guardar estado, reportar resultados y obtener recursos protegidos. La plataforma ya debe autenticar a sus usuarios.

Herramienta externa LTI 1.3

Un LMS puede abrir recursos P2LRN mediante un gateway LTI que reciba lanzamientos autenticados. Es la vía prevista para Moodle, Canvas, Sakai, Chamilo y Open edX, sujeto a versión y configuración. El gateway de producción de P2LRN todavía no está implementado.

Importación de archivos

Importar SCORM, H5P u otros materiales para reproducirlos dentro de P2LRN es una capacidad del formato y sus renderers; no es lo mismo que disponer de un plugin LTI activo en cada LMS.

No se necesita convertir cada .p2lrn a SCORM para usar LTI, ni desarrollar un Player distinto por LMS.

El recorrido común previsto

  1. Administrador: registra una herramienta externa confiable en el LMS y autoriza el despliegue y los servicios necesarios.
  2. Profesor: incorpora la herramienta a una actividad, selecciona un curso o lección publicados mediante Deep Linking y conserva el enlace a la revisión deseada.
  3. Alumno: inicia desde su LMS; el gateway comprueba la identidad, el despliegue, el contenido y los permisos, y abre Player.
  4. Progreso: la aplicación anfitriona guarda los intentos y la reanudación con el Host Adapter, separados por alumno, curso y versión.
  5. Notas: el backend comprueba los resultados antes de registrar o enviar una puntuación oficial mediante AGS cuando el LMS lo admita.
Este recorrido está diseñado, no desplegado

Los pasos de registro, selección y envío de notas describen el funcionamiento esperado del gateway universal. Hoy no hay una URL P2LRN LTI lista para pegar en cualquier LMS.

Moodle

La vía prevista es Herramienta externa LTI 1.3. El administrador habilita el uso de herramientas externas y registra el issuer y los parámetros suministrados por el proveedor. El profesor podrá usar Deep Linking si la versión de Moodle y el despliegue lo soportan.

Seguimiento: AGS permite enviar calificaciones sólo si hay permisos y un backend que valide el resultado. El resto de la actividad sigue reproduciéndose con el Player común.

Canvas LMS

El administrador configura una herramienta LTI 1.3 mediante los mecanismos de registro y Developer Keys de la instancia. La selección de recursos puede usar Deep Linking y el libro de calificaciones AGS cuando estén habilitados por la institución.

El identificador de un recurso de Canvas no debe sustituir la identidad portable del paquete. Una copia de un curso puede cambiar los IDs propios del LMS sin alterar el contenido autorizado.

Sakai

El acceso previsto utiliza las herramientas externas LTI de Sakai. Antes de activarlo hay que identificar la versión y comprobar que el despliegue soporta LTI 1.3, el modo de lanzamiento y las capacidades de notas realmente instaladas.

El Gateway P2LRN validará el mismo contrato de identidad y contenido que para Moodle o Canvas, sin crear código especial de Player para Sakai.

Chamilo

La disponibilidad concreta de LTI 1.3 y sus servicios varía según la versión de Chamilo y los componentes configurados. Primero hay que comprobar las capacidades efectivas de esa instancia; no se debe prometer Deep Linking ni AGS sin verificarlos.

Si no existe un consumidor LTI 1.3 compatible, la alternativa requiere una integración propia del host con Player y autenticación de la plataforma, no una simulación insegura de LTI.

Open edX

El recorrido previsto pasa por el componente LTI Consumer XBlock configurado para LTI 1.3. La apertura del recurso y la entrega de calificaciones dependen de la versión instalada y de los servicios autorizados.

Debe probarse la experiencia del alumno con las restricciones reales del sitio: sesión, incrustación, persistencia y finalización.

AulaP2P

AulaP2P puede incorporar de forma nativa el mismo Player P2LRN mediante Host Adapter para cursos y lecciones dentro de su propia plataforma. Las cuentas, roles, matrículas, permisos y calificaciones se mantienen en el backend de AulaP2P.

El repositorio de AulaP2P ya contiene implementación LTI destinada a su integración existente, pero eso no acredita que exista un proveedor universal P2LRN LTI completado. La ampliación debe reutilizar los controles LTI existentes y no duplicar autenticación ni alterar cursos SCORM previos.

Datos que corresponden al LMS y a P2LRN

En el paquete P2LRN

Contenido, grafo de unidades y actividades, recursos, perfil de reproducción y packageId + contentRoot para identificar la revisión portable.

En el LMS o servidor anfitrión

Usuarios, matrícula, políticas de centro, intentos privados, tokens, permisos, calificaciones oficiales, sesiones y almacenamiento durable.

En Host Adapter

loadState, saveState, reportScore, emitEvent y resolveResourceUrl. El navegador entrega datos; la autorización y la validación final siguen en servidor.

En el gateway LTI propuesto

Registro por institución, verificación OIDC, enlace a contenido publicado, control de sesiones y envío autorizado AGS.

Pruebas necesarias antes de anunciar compatibilidad

  • Administrador registra el despliegue y rechaza un issuer o client ID desconocidos.
  • Profesor selecciona una actividad publicada y puede copiar un curso sin perder el vínculo autorizado.
  • Alumno reanuda el contenido correcto desde dos sesiones y nunca accede al de otro centro.
  • Notas verificadas llegan al libro de notas correcto, sin duplicaciones ni aceptar puntuaciones manipuladas.
  • Probar cuestionarios, juegos 3D, contenido SCORM/H5P, recursos protegidos y vista móvil en cada versión real de LMS.

El detalle del estándar y los componentes pendientes están en Módulo LTI 1.3. Para integrar Player hoy en una web propia usa la guía de integración.
