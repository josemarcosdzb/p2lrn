Conectores de P2LRN

Conecta tus cursos con herramientas de IA, clientes locales y plataformas LMS. El formato .p2lrn, el Player y los contratos de integración son comunes: no es necesario crear un formato distinto por plataforma.

Conectores de inteligencia artificial

ChatGPT

Un creador P2LRN habilitado dentro de ChatGPT puede generar paquetes descargables sin túnel. Para acceder a tus cursos mediante MCP remoto necesitas registrar un servidor HTTPS autenticado; el ZIP generado en integration/mcp/ es privado de desarrollo, no un plugin aprobado en el catálogo público.

Claude

Claude web puede usar un servidor MCP remoto autorizado si el plan admite conectores personalizados. Claude Desktop admite conexión local por stdio.

Grok

La configuración preparada por P2LRN permite registrar el mismo endpoint MCP como conector personalizado, cuando la cuenta permite configurarlo. No supone una instalación automática ni publicación pública.

El servidor MCP existente ofrece lectura, búsqueda y validación de cursos. Con autorización explícita puede crear y editar borradores aislados y exportar nuevos paquetes sin reemplazar originales.

Plugin local y modelos del ordenador

En Windows, abre integration/mcp/Conectar-P2LRN.cmd en el repositorio de P2LRN. El asistente prepara las dependencias, pide la carpeta de cursos que deseas autorizar, detecta clientes y solicita confirmación antes de modificar su configuración. Funciona mediante MCP stdio sin un túnel de Internet.

Instalación guiada

Claude Desktop, Cursor, Windsurf, Gemini CLI y VS Code. Codex CLI, Claude Code, OpenCode y clientes genéricos MCP reciben instrucciones o configuración para revisar.

Pruebas con modelo local

El repositorio incluye ensayos con Ollama en 127.0.0.1:11434 y qwen3:4b por defecto. Son pruebas de laboratorio, no certificación de un agente autónomo.

Seguridad

Por defecto, P2LRN_MCP_WRITE=0: sólo lectura. Al habilitar edición se trabaja sobre borradores y nuevos archivos exportados.

PowerShell · desde el repositorio
node integration/mcp/connect-local.mjs
node integration/mcp/connect-local.mjs --root C:\MisCursos --clients claude,cursor,windsurf,gemini --install --verify

El ejecutable .cmd es la ruta recomendada, pues comprueba también la preparación del Toolkit.

Conexión IA web mediante MCP

El servidor HTTP de P2LRN está restringido a 127.0.0.1:37871/mcp. Un cliente web necesita un proxy o túnel HTTPS autenticado, con controles de origen y autorización. No abras ese puerto directamente a Internet ni incluyas credenciales en paquetes o enlaces.

Preparar descriptores de conexión
cd integration\mcp
npm install --ignore-scripts
node prepare-connectors.mjs --endpoint https://tu-dominio.example/mcp --out .generated\connectors

El comando genera un ZIP de desarrollo para ChatGPT y archivos de configuración para Claude y Grok. El servicio público multiusuario requiere OAuth, autorización individual y validación externa antes de distribuirse.

Integración con plataformas LMS

Moodle

Herramienta externa LTI 1.3; Deep Linking y AGS según la versión y la configuración.

Canvas LMS

Developer Key y herramienta LTI 1.3; enlace de contenidos y notas mediante los servicios habilitados.

Sakai

Herramientas externas LTI 1.3; disponibilidad de los servicios según la instancia.

Chamilo

Debe comprobarse la compatibilidad LTI de la versión y los módulos instalados.

Open edX

Integración prevista mediante LTI Consumer XBlock 1.3.

AulaP2P

Puede integrar el Player mediante Host Adapter. Su código LTI existente no equivale a un proveedor P2LRN certificado.

El Player y Host Adapter ya ofrecen reproducción y operaciones de carga de estado, guardado, puntuación, eventos y recursos. La matrícula, la identidad del alumno, la autorización y el libro de notas continúan siendo responsabilidad del LMS.

Módulo LTI 1.3

Arquitectura objetivo: LMS → gateway LTI 1.3 → Host Adapter → Player P2LRN. La herramienta externa permitiría a un profesor seleccionar cursos o actividades publicadas, y al alumno acceder desde su LMS con identidad verificada.

OIDC y JWKS

Inicio y lanzamiento seguro con verificación de firma, issuer, client ID, deployment ID, state y nonce.

Deep Linking

Selector de curso, unidad o actividad publicados y asociación a una revisión concreta mediante identificadores opacos.

AGS

Envío al libro de notas tras verificación del resultado en el servidor, nunca aceptando una calificación del navegador como definitiva.

NRPS

Servicio opcional de miembros y roles si la plataforma y los permisos lo ofrecen.

Estado técnico actual

P2LRN tiene arquitectura y contratos iniciales en integration/lms/, pero aún no dispone de un gateway LTI completo con OIDC/JWKS/launch, catálogo Deep Linking y AGS desplegados y verificados con LMS reales. Las rutas /lti/login, /lti/launch y /lti/jwks son previstas, no endpoints públicos operativos.

Qué debe comprobarse antes de producción

  1. Servidor MCP remoto autenticado y autorización individual de los cursos; comprobar las herramientas de cada IA.
  2. Instalación y lectura/escritura autorizada con cada aplicación local real.
  3. Registro y comprobación criptográfica del proveedor LTI, sesiones y catálogo de contenido publicado.
  4. Pruebas completas en Moodle, Canvas, Sakai, Chamilo, Open edX y AulaP2P con docentes, alumnos, reanudación y notas.
