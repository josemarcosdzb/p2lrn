Sección para desarrolladores e integradores. Aquí se explican las reglas y los datos que intercambian los componentes. Si estás preparando una lección, comienza con la guía de Studio para profesores; no necesitas escribir estos contratos.

DESARROLLADORES / CONCEPTOS

Conceptos fundamentales

Estas son las ideas que aparecen en el resto de la documentación. Entenderlas primero hace que las páginas de formato, autoría, Player e integración resulten mucho más directas.

1. Proyecto de autoría (workspace) y paquete

Un workspace es el proyecto editable de autoría: puede contener archivos fuente, configuración y datos intermedios. Un paquete .p2lrn es el artefacto portable que se entrega al Player. Puedes conservar el workspace para seguir editando y publicar sólo el paquete generado.

2. Manifiesto (manifest): identidad, capacidades e integridad

El manifiesto identifica el paquete, declara perfiles y puntos de entrada (entrypoints) y describe la integridad del contenido. Es la primera capa que el Player necesita para saber qué contiene el curso y qué capacidades debe comprender antes de reproducirlo.

3. Grafo (graph): la estructura navegable

El grafo describe cursos, unidades, actividades, recursos y relaciones. Las unidades organizan; las actividades representan pasos que el alumno puede completar; los recursos apuntan al contenido que una actividad necesita. Los entrypoints indican desde qué entidad puede empezar una reproducción.

4. Recurso y representación

Un recurso puede tener una o más representaciones. La representación explica cómo está disponible ese contenido: como miembro del paquete, contenido embebido, recurso externo compatible u otra forma declarada por el formato. Player no debe adivinar cómo abrirlo; el contrato de la representación lo indica.

5. Perfiles (profiles): reglas adicionales

Un perfil añade reglas que no forman parte del núcleo mínimo. Progresión y cuestionarios son ejemplos claros: el manifiesto declara el perfil y las entidades usan sus extensiones. Si una regla cambia la navegación —por ejemplo, bloqueos de progresión— el perfil debe declararse con el nivel de requisito adecuado para que un Player incompatible no pueda ignorarlo silenciosamente.

6. Renderizador y entorno de ejecución

El renderizador convierte una representación en una interfaz para el alumno. Algunos contenidos además necesitan un entorno de ejecución aislado, por ejemplo para ejecutar paquetes web externos. Elegir una presentación no modifica el contenido original: sólo cambia la forma de entregarlo cuando la representación es compatible.

7. Player y plataforma

Player se ocupa de abrir, verificar y reproducir. La aplicación que lo integra —el Host— se ocupa de usuarios, autorización y persistencia. Host Adapter define la comunicación entre ambos para cargar y guardar estado, reportar puntuación, enviar eventos y resolver recursos protegidos.

8. Integridad: confiar en lo que se reproduce

P2LRN utiliza hashes y una raíz de contenido para detectar modificaciones inesperadas. El objetivo no es sólo comprobar el archivo inicial: los recursos que el Player consume también deben respetar el contrato de integridad. Multipart mantiene esa propiedad cuando un recurso se distribuye en partes externas.

9. Modelo mental rápido

AUTORÍA

Studio o Toolkit producen el curso.

PAQUETE

Manifest + graph + recursos + perfiles.

REPRODUCCIÓN

Player verifica y renderiza.

PLATAFORMA

Host conserva identidad y estado.
