BUILD / PLAYER

Player web

Desde la primera línea HTML hasta eventos, CORS, Host Adapter, runtimes aislados y Service Worker.

Qué vas a conseguir

Montar <p2lrn-player>, cargar un paquete real y entender qué debe hacer tu aplicación alrededor del Player.

CDN o npm

Usa CDN para una integración directa sin build. Usa npm cuando quieras empaquetar el Player con tu aplicación.

CDN
<script src="https://p2lrn.netlify.app/player/current/dist/p2lrn.js"></script>
<p2lrn-player src="/courses/course.p2lrn"></p2lrn-player>
npm
npm install @p2lrn/player

import '@p2lrn/player';

Eventos

JavaScript
const player = document.querySelector('p2lrn-player');

player.addEventListener('p2lrn:ready', () => {
  console.log('ready');
});

player.addEventListener('p2lrn:rendered', (event) => {
  console.log('rendered', event.detail);
});

player.addEventListener('p2lrn:error', (event) => {
  console.error(event.detail);
});

El runtime también puede emitir actividad, progreso, estado, score y completion según las capacidades del renderer.

Host Adapter

La integración con identidad, autorización, matrícula, persistencia y URLs protegidas pertenece al host. El Adapter es el punto de integración; el paquete no debe contener credenciales del usuario.

CORS

Si src apunta a otro origen, ese servidor debe permitir las solicitudes del navegador. Para contenido privado, restringe orígenes o usa URLs autorizadas; no conviertas * en el mecanismo de autorización.

H5P y SCORM

El Player dispone de hosts aislados para estos runtimes. H5P puede resolver librerías compartidas fuera del paquete cuando la integración las distribuye como corpus reusable.

Runtime Node y runtime estático

Una instalación puede servir los hosts estáticos junto al frontend o exponerlos desde un host Node controlado. runtime-base-url permite cambiar el origen utilizado por el Player.

Service Worker

No es obligatorio para la reproducción normal. Se instala cuando la aplicación necesita acceso verificable a media seekable o una ruta virtual controlada.

Probar el Player real

El visor público P2LRN carga los paquetes canónicos publicados y muestra los eventos del runtime para que puedas comprobar el comportamiento antes de integrarlo.

Errores habituales

Empieza por p2lrn:error, red/CORS, integridad del paquete y disponibilidad del renderer/runtime. La guía completa está en Troubleshooting.
