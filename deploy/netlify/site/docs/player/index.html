Player web

El Player abre un .p2lrn, verifica manifest y graph, selecciona un renderer compatible y conecta el runtime con la aplicación host.

Integración mínima

CDN
<script src="https://p2lrn.netlify.app/player/current/dist/p2lrn.js"></script>
<p2lrn-player id="course" src="/courses/course.p2lrn"></p2lrn-player>
npm
npm install @p2lrn/player@0.5.0-alpha.10

import '@p2lrn/player';

Web Component

src

URL del paquete. Es el atributo que inicia la carga.

node

ID de entidad inicial opcional.

renderer

Renderer solicitado explícitamente; si no es obligatorio se permite fallback ante incompatibilidad.

runtime-base-url

Origen base alternativo para hosts de runtime.

player.adapter

Host Adapter versión 1.

await player.reload()

Vuelve a abrir y renderizar el paquete.

API pública

P2LRN.mount(target, options)

Monta el Player y aplica src, node, renderer, runtimeBaseUrl y adapter.

P2LRN.openPackageURL(url, options)

Abre un paquete remoto. Usa transporte por rangos cuando el servidor lo permite.

P2LRN.openPackageBytes(buffer, limits)

Abre un paquete completo en memoria.

P2LRN.renderers()

Lista el registro actual de renderers.

P2LRN.installServiceWorker(options)

Instala el bridge de recursos verificados cuando la integración lo necesita.

Integridad y transporte

El Player valida contentRoot, manifest, graph y cada payload cuando se consume. La apertura remota puede ser eager o lazy según el transporte. Con HTTP Range, manifest y graph se verifican primero y el payload se verifica bajo demanda.

Límites por defecto

Buffer completo: 256 MiB. Paquete remoto: hasta 64 GiB. Entradas: 5000. Estos límites son controles del runtime, no una recomendación de tamaño de curso.

Eventos reales

JavaScript
const player = document.querySelector('p2lrn-player');

for (const type of [
  'p2lrn:ready',
  'p2lrn:rendered',
  'p2lrn:score',
  'p2lrn:statechange',
  'p2lrn:complete',
  'p2lrn:progressionchange',
  'p2lrn:error',
]) {
  player.addEventListener(type, (event) => {
    console.log(type, event.detail);
  });
}

Consulta Eventos para el contrato común de event.detail.

Host Adapter

El Adapter expone loadState, saveState, reportScore, emitEvent y resolveResourceUrl. El Player exige que una URL resuelta por el host declare verified:true; de lo contrario rechaza el recurso.

Ver integración Host completa →

Renderers incorporados

El runtime actual registra renderers para contenido web/texto, media, questionnaire estándar, juegos 2D, juego 3D Three.js + Rapier, componentes, composites, H5P, SCORM, QTI y un runtime genérico de paquete. La presencia de un renderer no equivale por sí sola a soporte de autoría o round-trip.

Juegos 3D

El renderer 3D utiliza Three.js para la escena y Rapier para físicas. Las mecánicas de ordenar, relacionar y clasificar son código P2LRN independiente del motor gráfico y no dependen de AulaP2P. Ver arquitectura y ejemplo 3D →

Service Worker

Se usa para exponer recursos verificados mediante la ruta virtual del Player. No lo presentes como requisito universal: sólo instálalo cuando el renderer o la estrategia de entrega necesiten una URL navegable para contenido ya verificado.

Probar antes de integrar

El visor público usa P2LRN.openPackageURL() y el mismo Web Component publicado. Muestra format, versión, contentRoot, perfiles, transporte, renderer y eventos.
