DESARROLLADORES / DIAGNÓSTICO

Solución de problemas

Guía técnica para diagnosticar la instalación, la reproducción y la integración de P2LRN en una web o LMS. Si eres profesor y una actividad no se abre en Studio, empieza por la guía del editor. Si administras el sistema, revisa los errores de Player sin desactivar las comprobaciones de integridad.

Player no carga

  1. 1.Comprueba que /player/current/dist/p2lrn.js responde.
  2. 2.Ejecuta customElements.get('p2lrn-player').
  3. 3.Comprueba src y Network.
  4. 4.Escucha p2lrn:error.
  5. 5.Si el paquete abre pero no renderiza, revisa presentación o entorno de ejecución.

CORS

Síntoma: la petición al paquete o a una parte externa falla antes de que el Player pueda verificarla. Comprueba el origen de la aplicación, la respuesta OPTIONS cuando exista preflight y Access-Control-Allow-Origin. * sólo abre lectura cross-origin; no autoriza a un usuario.

Error de integridad de contentRoot o digest

El paquete, graph o payload cambió después de calcular integridad o llegó corrupto. Vuelve a generar o recuperar el artefacto correcto. No edites manualmente el digest para que coincida.

Presentación no disponible

Consulta P2LRN.renderizadors(). Si fijaste renderizador, verifica que su id exista y que acepte profile/mediaType/ubicación de la representación. El Player sólo hace fallback en categorías de incompatibilidad previstas.

Multipart: falta una parte

El descriptor usa href relativos al .p2lrn. Verifica que todas las .partNNN se publiquen junto al paquete y no se renombren. Si una parte existe pero cambia, su SHA-256 debe fallar.

HTTP Range

El Player puede abrir paquetes remotos por rangos. Si el servidor no soporta el patrón esperado, revisa respuestas 206, Content-Range y límites de proxy/CDN. El transporte actual puede cambiar a lectura completa cuando no dispone de range.

El runtime configurado comparte origen con la aplicación

SCORM y H5P: el Player cambia automáticamente al sandbox interno de origen opaco. No necesitas crear otro dominio sólo para reproducir estos contenidos.

Runtime administrado o paquete ejecutable genérico: si has configurado runtime-base-url expresamente para un entorno que exige otro origen, utiliza un dominio, subdominio o puerto diferente. Una ruta diferente en el mismo origen no constituye aislamiento.

\n

Falta una librería H5P

El sandbox automático intenta completar las dependencias que no estén dentro del .h5p utilizando el catálogo runtime-host/h5p-libraries/index.json situado junto al Player. Comprueba que ese corpus se publica junto con los assets del runtime. Si utilizas el runtime Node opcional, comprueba también el directorio de librerías configurado en ese servicio.

SCORM no arranca

Comprueba que el punto de entrada SCORM existe dentro del paquete y que el navegador permite el iframe sandbox. Si el runtime configurado comparte origen con la aplicación, el Player utiliza automáticamente el sandbox interno en lugar de exigir otro servidor.

No llega el evento de finalización

El contrato actual del Player usa p2lrn:complete, no p2lrn:completion. Para estado usa p2lrn:statechange; para cambios de progresión usa p2lrn:progressionchange. Verifica además que el renderizador concreto emita ese evento.

Fallo al guardar progreso

Si Host Adapter.saveState() falla, el Player emite p2lrn:error con fase progression-save. El estado de alumno pertenece al Host; no intentes escribirlo dentro del paquete.

Diagnóstico rápido

Ejecuta estas comprobaciones en la consola cuando necesites distinguir rápidamente entre un problema de carga, montaje del Player o disponibilidad de la API.

JavaScript
const player = document.querySelector('p2lrn-player');

player.addEventListener('p2lrn:error', (event) => {
  console.error(event.detail);
});

console.table(P2LRN.renderizadors());
console.log(P2LRN.version, P2LRN.toolkitVersion);

Contactar

Si P2LRN no funciona dentro de un LMS

Empieza por identificar si el problema ocurre al instalar, al abrir la actividad, al subir el curso o al recibir la nota. Estas comprobaciones se basan en incidencias encontradas al conectar Moodle, Canvas, Chamilo, Sakai y Open edX.

No aparece P2LRN al añadir una actividad

Pide al administrador que compruebe que la herramienta está activa para el curso o institución. En Moodle: «Administración del sitio → Plugins → Herramienta externa → Gestionar herramientas» y «Mostrar en selector de actividades y como herramienta preconfigurada». No hace falta modificar SQL.

El botón de subir archivos no se muestra

El LMS debe abrir la opción de selección de contenido (Deep Linking), no solamente un enlace de reproducción existente. Comprueba los permisos del profesor, la configuración de la herramienta y si esa versión del LMS admite el selector.

Inicio de sesión redirigido o bloqueado

Canvas y Open edX pueden depender de la autenticación central del centro. Completa esa autenticación con una cuenta autorizada; no sustituyas el acceso por enlaces internos ni introduzcas credenciales técnicas en el paquete.

Error 403, origen no autorizado o página en blanco

Comprueba que las URL de inicio, lanzamiento y claves públicas utilizan el mismo dominio HTTPS configurado, y que la institución ha autorizado la herramienta. Las cookies de terceros o las políticas de iframes pueden afectar al lanzamiento. No desactives firma, state ni nonce.

Error 502, nombre Docker no encontrado o LMS inaccesible

Comprueba el estado del proveedor, la resolución DNS, el proxy HTTPS y las redes declaradas en Compose. En laboratorios locales usa redes externas persistentes; no dependas de conexiones manuales que se pierden al recrear el contenedor.

Error 413 o curso no aceptado

El selector admite archivos .p2lrn de hasta 64 MB. Comprueba el tamaño permitido por el proxy y el formato del archivo. No eludas la validación de integridad del paquete.

El alumno responde pero no aparece la nota

Comprueba que el LMS autoriza AGS, que existe un intento de alumno real y que la calificación se ha aprobado y aceptado en el libro oficial. La pantalla «Respuestas entregadas» no es una confirmación de AGS.

Los datos desaparecen al actualizar Docker

Conserva el volumen de cursos y SQLite, y las mismas claves RSA. No confundas «reiniciar» con «recrear»: la recreación exige que el fichero Compose describa todos los volúmenes y redes necesarios.

Si el problema continúa, registra la fase, el LMS y su versión, el mensaje visible y una captura sin contraseñas, tokens ni datos de alumnos. Consulta la instalación y el diagnóstico del proveedor LTI.

Chamilo 2.0.3: HTTP 500 al configurar herramientas LTI. El complemento IMS/LTI 1.9.0 puede utilizar campos retirados de Doctrine, pasar códigos de curso cuando se requiere un ID numérico y emplear una API antigua de Firebase JWT para el retorno Deep Linking. Comprueba la versión instalada y la incidencia de Chamilo. Hay una adaptación aislada para el laboratorio en integration/lms/chamilo-compat del código de P2LRN; todavía no es una actualización universal de producción.

Inicio de sesión gestionado: algunos centros redirigen el acceso del LMS a su proveedor de identidad. Debe completarse ese inicio de sesión legítimo antes de usar el selector del profesor; no hay que desactivar la autorización ni fabricar un lanzamiento firmado. P2LRN no exige crear una cuenta en otra plataforma para abrir actividades desde un LMS externo autorizado.
