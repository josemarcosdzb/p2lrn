01 · QUÉ ES

El curso viaja como un paquete verificable.

P2LRN guarda en un mismo paquete la estructura del curso, sus activos, sus manifiestos y las referencias necesarias para poder abrirlo y reproducirlo después.

Portabilidad

El contenido no queda ligado a una base de datos o a una interfaz concreta. El archivo .p2lrn puede moverse entre aplicaciones compatibles.

Integridad

Manifiestos, digests y contentRoot permiten comprobar que el contenido que se abre es el mismo que se empaquetó.

Separación

El paquete describe el curso. La plataforma conserva usuarios, permisos, matrícula, credenciales, telemetría y persistencia durable.

02 · CÓMO FUNCIONA

Tres pasos: empaquetar, verificar y reproducir.

El flujo está pensado para que cada capa tenga una responsabilidad concreta.

1

PACKAGE

El Toolkit crea o abre un paquete .p2lrn con la estructura del curso, recursos y metadatos.

2

VERIFY

Antes de usar el contenido se comprueban manifiestos, hashes y relaciones internas.

3

RENDER

El Player negocia el renderer adecuado y, cuando hace falta, utiliza runtimes aislados para H5P, SCORM u otros formatos.

Fuera del paquete usuarios · permisos · matrícula · autenticación · URLs protegidas · persistencia · telemetría
03 · PLAYER

Reproducir un paquete en la web.

El Player se distribuye como Web Component. La integración mínima sólo necesita cargar el runtime y apuntar al archivo del curso.

HTML 
<script src="https://p2lrn.netlify.app/player/current/dist/p2lrn.js"></script>

<p2lrn-player src="/courses/course.p2lrn"></p2lrn-player>

Propiedades principales

src

URL del paquete. Es la única propiedad obligatoria para iniciar la reproducción.

obligatoria
node

Permite abrir directamente un nodo concreto del grafo del curso.

opcional
renderer

Fija un renderer concreto cuando la integración necesita una elección estricta.

opcional
runtime-base-url

Permite utilizar otro origen de confianza para los hosts de runtime aislados.

opcional
04 · TOOLKIT

Crear, leer, validar y transformar paquetes.

El Toolkit es la parte de Node/TypeScript de P2LRN. Incluye APIs de autoría, Reader, Creator, validación, conversión y utilidades de línea de comandos.

$ npm install @p2lrn/toolkit @p2lrn/player

Autoría

La API pública está en @p2lrn/toolkit/authoring. Un editor puede trabajar contra esa frontera sin acoplarse a módulos internos.

Reader

Abre e inspecciona paquetes P2LRN. El Reader documental ligero cubre DOCX, PPTX, ODT, EPUB y texto estructurado.

Conversión

Incluye herramientas para convertir, repaquetar y preservar contenido externo manteniendo las reglas de integridad del formato.

Compatibilidad legacy

P2RLN Alpha15 y sus identificadores históricos siguen siendo legibles para no romper paquetes anteriores. Esa compatibilidad no convierte esos nombres antiguos en la autoridad nueva.

Runtimes externos

H5P y SCORM disponen de hosts aislados. cmi5, QTI, Common Cartridge, IMS Content Package y Tin Can se tratan según las capacidades reales disponibles.

Preservar no significa ejecutar. Un contenido externo no se declara reproducible si no existe un runtime real que lo soporte.

Qué sirve este CDN

El despliegue público sirve el Player, los hosts de runtime y librerías H5P reutilizables. No almacena cursos de usuario ni información personal.
