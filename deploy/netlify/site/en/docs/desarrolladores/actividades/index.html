Data contract, code examples and Player integration for this activity. The visual authoring walkthrough is in the separate teacher guide.

Technical gap markers can be written as {{id}} or ___.

The same questionnaire, different experiences

Questions are saved as application/vnd.p2lrn.questionnaire+json. The chosen presentation does not create another copy of the content: it tells the Player how to display that questionnaire.

The presentation should never miss questions.

If the entire questionnaire cannot be faithfully represented mechanically, that presentation is considered incompatible. P2LRN does not eliminate questions or invent answers to make it fit.

Status and score

All submissions update the same questionnaire status. To hear punctuation and completion use Events; To persist them on a platform, configure Host Adapter.

Test before integrating

The viewer allows you to open example packages and change presentation when the content is compatible.

Create and verify your own exercises in Studio. Native test courses are no longer published.

Teacher guide for this activity

Standard quiz

Data contract, code examples and Player integration for this activity. The visual authoring walkthrough is in the separate teacher guide.

Content requirements

  • Supports native quiz question types.
  • You can use embedded solution remediation or platform-managed remediation.
  • The presentation can show one question at a time or all at once.

Valid data example

This example shows the data used by the activity for CLI authoring. In Studio, configure the corresponding content using the visual editor.

quiz.json
{
  "schema": "https://p2lrn.org/schema/native-questionnaire/0.4.0",
  "version": "0.4.0",
  "title": "Quick check",
  "language": "en",
  "grading": {
    "mode": "embedded-key"
  },
  "presentation": {
    "questionMode": "one-at-a-time",
    "shuffleQuestions": false,
    "showFeedback": "after-submit"
  },
  "questions": [
    {
      "id": "q1",
      "type": "single-choice",
      "prompt": "Capital of Portugal",
      "points": 1,
      "choices": [
        {
          "id": "a",
          "text": "Lisbon"
        },
        {
          "id": "b",
          "text": "Madrid"
        }
      ],
      "solution": {
        "choiceIds": [
          "a"
        ]
      }
    }
  ]
}

How to read the example

The example contains a single choice question. choices defines the options and solution.choiceIds Identify the correct answer.

Create by CLI — advanced alternative

Use these commands for code-based authoring with Toolkit installed via npm. The quiz.json file must contain a valid questionnaire like the example above.

Terminal
p2lrn-create add-questionnaire ./workspace ./quiz.json \
  --key quiz \
  --title "Standard questionnaire" \
  --renderer "https://p2lrn.org/renderer/questionnaire/standard"

p2lrn-create build ./workspace ./course.p2lrn --strict-profiles

--renderer Select the preferred presentation. It does not create a second copy of the questions: the content remains the native questionnaire.

Memory

Data contract, code examples and Player integration for this activity. The visual authoring walkthrough is in the separate teacher guide.

Content requirements

  • In Studio, the Memory preset is edited as a question type Matching.
  • The activity needs embedded solutions and at least three pairs.
  • Clues and answers should not be repeated in a way that makes a pair ambiguous.
Additional Player support.

The Player can also convert other question types into pairs when all relationships can be deduced unambiguously. Studio uses Relate because it is the clearest visual format to create this game.

Valid data example

This example shows the data used by the activity for CLI authoring. In Studio, configure the corresponding content using the visual editor.

quiz.json
{
  "schema": "https://p2lrn.org/schema/native-questionnaire/0.4.0",
  "version": "0.4.0",
  "title": "Match countries and capitals",
  "language": "en",
  "grading": {
    "mode": "embedded-key"
  },
  "questions": [
    {
      "id": "q1",
      "type": "matching",
      "prompt": "Match each country with its capital",
      "points": 3,
      "left": [
        {
          "id": "l1",
          "text": "Spain"
        },
        {
          "id": "l2",
          "text": "France"
        },
        {
          "id": "l3",
          "text": "Italy"
        }
      ],
      "right": [
        {
          "id": "r1",
          "text": "Madrid"
        },
        {
          "id": "r2",
          "text": "Paris"
        },
        {
          "id": "r3",
          "text": "Rome"
        }
      ],
      "solution": {
        "pairs": [
          {
            "left": "l1",
            "right": "r1"
          },
          {
            "left": "l2",
            "right": "r2"
          },
          {
            "left": "l3",
            "right": "r3"
          }
        ]
      }
    }
  ]
}

How to read the example

The example uses a question matching with three elements on each side. solution.pairs declares the three relationships and allows the six cards to be constructed.

Content requirements

Teacher guide for this activity

Ordering

Data contract, code examples and Player integration for this activity. The visual authoring walkthrough is in the separate teacher guide.

Content requirements

  • In Studio it is created as a question of type Ordering.
  • Each sequence must have at least three elements.
  • solution.order must contain all identifiers exactly once.
  • The activity requires embedded solutions.

Valid data example

This example shows the data used by the activity for CLI authoring. In Studio, configure the corresponding content using the visual editor.

quiz.json
{
  "schema": "https://p2lrn.org/schema/native-questionnaire/0.4.0",
  "version": "0.4.0",
  "title": "Order the water cycle",
  "language": "en",
  "grading": {
    "mode": "embedded-key"
  },
  "questions": [
    {
      "id": "q1",
      "type": "ordering",
      "prompt": "Order the stages",
      "points": 3,
      "items": [
        {
          "id": "i1",
          "text": "Evaporation"
        },
        {
          "id": "i2",
          "text": "Condensation"
        },
        {
          "id": "i3",
          "text": "Precipitation"
        }
      ],
      "solution": {
        "order": [
          "i1",
          "i2",
          "i3"
        ]
      }
    }
  ]
}

How to read the example

items contains the visible elements. solution.order declares the correct sequence using its identifiers.
