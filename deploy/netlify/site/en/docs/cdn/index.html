INSTALLATION / CDN

Installation via CDN

Use this guide when you want to load P2LRN directly from HTML using published browser files. Player and Studio have separate entry points.

1. Load the Player

Add the loader only once on the page. Then you can use the element <p2lrn-player> as many times as you need.

HTML
<script src="__P2LRN_PINNED_PLAYER_URL__" integrity="__P2LRN_PINNED_PLAYER_SRI__" crossorigin="anonymous" referrerpolicy="no-referrer"></script>

<p2lrn-player src="./course.p2lrn"></p2lrn-player>

The channel current points to the version published for regular use.

2. Set a Player version

When you need a reproducible integration, replace the channel current for a specific version to keep the file that loads your application stable.

HTML
<script src="https://p2lrn.org/player/0.5.0-alpha.13/dist/p2lrn.js"></script>

A versioned URL maintains the same version of the file as long as that publication is available.

SRI protection for CDN distributions

Production integrations should use the immutable /player/VERSION/dist/p2lrn.js URL rather than mutable /player/current/. Each build publishes exact SHA-384 hashes in the SRI manifest and in /index.json (player.integrity.classic). Pin the corresponding digest in your integration HTML using integrity="sha384-…", crossorigin="anonymous", and referrerpolicy="no-referrer".

Pin the hash at your own build or deploy time. Do not fetch the hash dynamically from the same CDN at runtime: a compromised CDN could replace the script and manifest together. Root-script SRI does not automatically cover every imported module; preserve origin isolation, CSP and deployment controls.

3. Load Studio

Studio has its own web loader. The specific guide explains the assembly, opening courses and connecting with saving and import services.

Complete Studio Guide via CDN

4. What happens when the script loads

The loader registers the component <p2lrn-player> in the browser. From that moment on you can use it in the HTML and assign a package to it using src. You do not need to copy the Player files to your project if you are going to use the published resource.

5. Open the page from a local server

Open the project folder in your regular text or code editor and serve it over HTTP. The browser needs a real web origin to correctly resolve the package and its resources; open index.html directamente mediante file:// It does not represent the normal operation of a web application.

  1. Locate index.html and the files used by the page.
  2. Start the preview or the local HTTP server that you normally use in your editor or development environment.
  3. Open the local address provided by that server in the browser.

You don't need an editor, an extension, or a specific tool for this step.

6. Load a course

The attribute src It can point to a file on the same site or to a URL allowed by the server hosting the content. If the course is on another source, configure CORS to allow it to be read.

7. Check the integration

Open the page from the web server, confirm that the Player appears, and check the browser console if the package does not load. The most common failures are an incorrect URL, a server that does not deliver the file, or a CORS policy that prevents reading it.

To learn about attributes, events, and integration with your platform, continue with Player.

Analytics via CDN

The basic integration reads the .p2lrn-result file from the src path. No metrics endpoint is required.

HTML
<script src="https://p2lrn.org/analytics/current/dist/p2lrn-analytics.js"></script>
<p2lrn-analytics id="panel.analytics" src="/resultados/ana.p2lrn-result"></p2lrn-analytics>

For multiple learners use a static result index or import local files. Complete CDN Analytics guide: identity modes, files and advanced options.
