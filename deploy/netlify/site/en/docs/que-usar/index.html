Component map

P2LRN is divided into small pieces with different responsibilities. Choosing the right part avoids duplicating functions of your application within the package.

1. The complete tour

Studio o Toolkit→.p2lrn→Player↕Host Adapter / Capability Broker↕your platform

Studio and Toolkit produce or modify the package. Player plays it. Host Adapter communicates status, score, events, and resources; Capability Broker connects optional live services such as collaboration without introducing endpoints or credentials into the course.

2. Main components

Studio

Visual editor for courses, images, quizzes, games, collaboration, shared resources, and activity groups.

Native components

Portable content without external dependencies, including text, image, video, Notice, tabs and timeline.

Toolkit

Authoring/Reader/validation/conversion, Reference Host and CLI.

Player

Open and check the package, negotiate capabilities, and play renderings.

Host Adapter

Status, score, events and protected resources.

Capability Broker

Optional live services like collaboration/AI without giving secrets to the course.

Offline Host Adapter

Local state and ordered outbox; You can synchronize when the network returns.

Package Cache

Preserve verified bytes of the course to reopen offline. Does not contain learner status.

Resource Library

Shared content-addressed library verified by SHA-256.

Host autoritativo

Server-side reference to separate evidence from official status/note browser.

Reader

Extract document structure to decide how to convert it to content.

Multipart

Verified transport of large resources outside the main file.

3. Which component to use depending on the task

A teacher creates a course

Studio.

A process generates many courses

Toolkit and CLI.

A website reproduces the course

Player.

Save progress or official notes

Host Adapter and authorized backend; uses the Authoritative Reference Host as a pattern, not as an identity system.

Continue working without network

Offline Host Adapter for state/outbox and Package Cache for course bytes.

Reuse resources between courses

Resource Library or remote representation with expectedDigest + resolver verificado.

Two learners collaborate

Capability Broker + Host collaboration provider.

Integrate into an LMS

Player/Host directo o proveedor LTI 1.3 self-hosted.

Import a document

Reader.

Very large resource

Multipart.

4. What should not be kept inside the package

The package contains structure, content, profiles and portable metadata. It should not be converted into a user database. Identity, passwords, permissions, license plates, secrets, individual progress and private data remain on the platform.

5. How the installation fits

NPM and CDN are ways to load browser components; They are not different products. Once the installation path is chosen, the Player or Studio API is the same for that version.
