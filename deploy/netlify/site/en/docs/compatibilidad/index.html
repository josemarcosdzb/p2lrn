Compatibility and migration

Not all capabilities mean the same. This table separates what P2LRN can create, open, read, preserve, and play to avoid promising a more complete migration than each format actually allows.

1. What each column means

Native

The format is part of P2LRN's own model.

Create

Toolkit can produce that content natively.

Open and rebuild

A package containing that profile can be opened as a project and rebuilt without losing the declared artifact.

Read

Reader can interpret useful structure or content from that format.

Preserve

P2LRN can transport the artifact even though it cannot fully edit or play it.

Play

The Toolkit declares a complete delivery route for that profile.

“Keep” does not mean “edit” or “reproduce.”

For example, an external package can travel intact within P2LRN even though its edition still belongs to another tool.

3. How to evaluate a migration

  1. Please check the column you need.If you want to edit, "Keep: yes" is not enough; you need a proper build or rebuild path.
  2. Test the resulting package.Open a real sample with the viewfinder and check resources, navigation and events.
  3. Check executable content.SCORM, H5P, cmi5, and other packages may require an isolated execution environment and additional resources.
  4. Don't assume semantic equivalence.Just because a file can be read or transported does not mean that all rules in the source LMS can be automatically converted.

4. External formats and Player

The Player has the infrastructure to run several external formats, but ultimate capability depends on whether a supported representation is included in the package and the necessary runtime environment is available. That's why the above matrix does not automatically convert "Read" or "Keep" to "Play".

For a specific integration, prepare a test package, open it with the Player and validate the entire journey before migrating content in bulk.

5. P2RLN Alpha15 Packages

P2RLN Alpha15 is a historical identity that predates P2LRN. If you receive such a package, you can repackage it with the current identifiers before continuing to work with it.

Terminal
p2lrn-repack old-course.p2rln new-course.p2lrn --canonicalize-identifiers

After converting, validate the new package and test it with Player before replacing the original.

Playback of external formats

Player runs SCORM, H5P, and other supported HTML content in an isolated environment and keeps learner state out of the package when persistence is provided by the integrating platform.

  • SCORM 1.2 and SCORM 2004: the runtime offers the documented tracking and persistence APIs; each package should be checked according to the version and extensions it uses.
  • H5P: Player can play compatible content using the available libraries. If content requires a non-distributed library, it must be incorporated before publishing it.
  • cmi5 and HTML: They can be run in isolation when the package and environment meet the requirements described in the documentation.
  • Dependencias externas: Remote services, server code, outdated technologies, or resources that do not travel with the course may require additional configuration or be unavailable.

Final compatibility depends on the specific package, browser, platform security policies, and external services you use. Always validate the actual contents in the target browsers before a deployment.
