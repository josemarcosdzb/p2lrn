What should be understood before the first integration

These three pages form the block Before you start. They are the vocabulary and the minimum structure necessary to understand the rest; They focus on concepts prior to installation, monitoring, persistence and analytics.

Authoring project, package, manifest, graph, resources, representations, profiles and renderers.

P2LRN format

What the package physically contains, how it is organized, and what data belongs to the host and not the course.

Progression and metrics go together, but more later

They are two parts of the same tracking problem, but they are not part of the introduction. Progression explains the rules that the course declares—mandatory, completion, approval, blocking, and unblocking. Metrics and analytics explains what actually happened during the execution and what data the platform should retain or analyze.

First understand the format, install, create and play. When you need to connect the learner journey with status, notes, events, and reports, go to Tracking and read Progression → Metrics and Analytics as a continuous block. To later view that data in an embeddable panel, continue in the section Analytics.

Analytics

P2LRN Analytics It now has its own section of the documentation. The embeddable dashboard brings together learners, courses, progress, activity, attempts, tracking signals, and authoritative notes without saving private data within the package .p2lrn.

Dashboard and views

Summary, learners, courses, notes and activity with filters, pagination and CSV export.

Host Data

Connect an authorized endpoint using src or createHttpAnalyticsDataSource; Identity, permissions and persistence remain on your platform.

CDN and NPM

Can be loaded from /analytics/current/dist/ or install as @p2lrn/analytics, maintaining the same version as the rest of the P2LRN packages.

The public Analytics app allows you to review the component and its navigation with a demo dataset.

If you only want to create a course with the hosted Studio

you can open Studio directly without installing anything. The installation phase is only necessary when you want to incorporate P2LRN into your own project or use the Toolkit from code.

If you want to send it to a learner without an LMS

Studio can generate a self-running offline delivery: the learner opens it in his browser, completes the activity and returns a single .p2lrn-result to review it later in Studio.

Responsibility of each piece

STUDIO

Visual editor to build courses, lessons, images, resources, games and collaboration.

TOOLKIT

API and CLI for creation, validation, reading and transformation.

PLAYER

Opens, verifies, and plays the package, negotiates capabilities, and emits events.

PLATFORM

Preserve users, permissions, progress, scores, collaborative services, verified resources, and secrets.

reading rule

Before you start It only groups Component Map, Fundamental Concepts and P2LRN Format. Quick start allows you to test the Player with CDN before entering the full installation. Next comes installation, creation, reproduction and integration. Tracking It groups Progression and Metrics and analytics because one defines the rules of the journey and the other measures its results.
