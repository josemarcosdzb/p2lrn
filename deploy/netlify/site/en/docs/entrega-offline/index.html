CREATE / DELIVERY WITHOUT A PLATFORM

Prepare an offline delivery with Studio

Prepare a course .p2lrn so learners can open it without relying on an educational platform or internet connection, complete it in their browser and return a single results file. Studio allows you to limit attempts, record activity and set an expiration from the first opening.

1. Before opening a delivery

Do not open an executable course of unknown origin.

The learner should continue only when they recognize the teacher, center or organization that has sent them the file and expected to receive that course. If the file arrives through an unexpected channel, has been forwarded by someone else, or Windows displays a provenance warning that you cannot justify, do not run it and confirm its origin first.

This recommendation applies to any executable file, not just P2LRN. The fact that a file has a P2LRN name or icon does not in itself prove who created it.

2. Delivery formats

4. Configure every field of the offline delivery

Open your course in P2LRN Studio and choose Offline delivery. This screenshot was captured from the actual editor. Open the image to inspect the form at full size; the settings below follow the same order as the interface.

Before generating the delivery, complete the course’s Author and Rights holder metadata and the Who delivers this course field. These fields serve different purposes: authoring rights and the sender shown to the learner.

Fields and their effects

01 Who delivers this course
Required. Enter the teacher, school or organisation responsible. Learners see this information before starting.
02 Delivery format
Choose Windows 64-bit EXE for a single executable, portable ZIP to extract and launch, or Windows CMD as an alternative. The selected format bundles the course and its packaged resources.
03 Learner ID (optional)
Assign a code before export, or leave it empty so it can be provided when the package is opened. The code links a result to a declared learner; it does not authenticate their identity.
04 Available from (optional)
Date and time when the delivery becomes available. Empty: no starting date. Fully offline enforcement depends on the device clock.
05 Deadline (optional)
Latest permitted date and time. Empty: no fixed deadline. It also applies alongside other configured limits.
06 Maximum time per attempt (minutes)
Time allowed after an attempt begins. Empty: no per-attempt time limit. Valid values are 1–44,640 minutes; this differs from the deadline.
07 Expires after first opening (days)
Number of days counted from the first launch on that device, not from the export date. Empty: no first-launch expiry. Valid values are 1–3,650 days.
08 Maximum attempts
How many attempts the learner can start for this delivery. Default is 1; valid values are 1–100. Fully offline enforcement is local to the device.
09 Allow attempt to be resumed
Enabled by default. Allows a pending attempt to continue using the supported save or transfer flow, without granting extra attempts.
10 Record metrics and active time
Enabled by default. Adds available learning activity and active-time records to the submitted result; it does not create official LMS grades.
11 Sign the assignment for later verification (optional)
Disabled by default. Generates a separate receipt for the teacher to save and use when verifying a returned assignment. Do not send the receipt as part of the learner package.

Example: choose ZIP, 1 maximum attempt, a 45-minute attempt duration and 14 days after first opening. Leave the dates empty if you do not need a calendar window. Generate delivery downloads the selected package; check that the file was saved before sharing it. Offline time and attempt restrictions do not prove identity or prevent copying on another computer.

Signed assignment: when enabled, download the separate teacher receipt and keep it privately; use Review delivery with the original course to inspect the returned .p2lrn-result.

5. What a self-running delivery records

In addition to the responses and scores generated by the course, the delivery may retain information about its use. The returned result may include:

  • number of registered openings;
  • date of first and last opening;
  • logged session history;
  • pseudonymous local identifier of the device;
  • expiration date calculated from first opening;
  • attempt made and duration;
  • active time and course events;
  • detected incidents, such as abnormal clock changes or use beyond established limits.

These data are incorporated into the .p2lrn-result so that the teacher can review them later.

6. Expiration and reuse

If the teacher establishes “Expires after first opening”, the period begins when the delivery is first opened. For example, with 30 days, a delivery opened on November 1st will be blocked on that computer after the 30 days are up.

What offline expiry can and cannot prevent.

Expiration reduces casual reuse and allows subsequent uses to be detected. In the Windows EXE the open state is saved outside the temporary course folder so that closing the browser or running the same file again does not reset the counter. However, a completely offline file cannot absolutely prevent someone from making a copy before opening it or moving it to another computer. Strict blocking between devices would require external activation or verification.

Upon expiration, P2LRN blocks access on the device where it is registered. There is no physical deletion of the file as a security measure: deleting a copy does not delete other copies that may already exist.

Move the course and resume the same attempt on another device

Progress cannot travel inside a browser's local storage. To move it, take two files: the same offline delivery (.exe, .zip or extracted folder) and the progress .p2lrn-result. The signed course remains unchanged; the result is a portable sidecar. No internet access or database is required.

  1. Device A: open the delivery with your individual learner code and work normally.
  2. Before changing devices: select Save progress for another device. This creates an in_progress .p2lrn-result checkpoint with the current answers and events. Verify that your browser actually saved the file.
  3. Transfer both: copy the same course EXE/ZIP and the progress file. Do not edit the course package or the JSON.
  4. Device B: open the same delivery, choose Import progress and continue, select the checkpoint, then select Continue attempt.
  5. When finished: select Finish and download result. The final .p2lrn-result retains the same learner and attempt identifiers with status submitted. Return this file to the teacher or import it into Analytics as the completed submission.

Import checks SHA-256, matching course/assignment version, learner code, attempt history and ordered records. It never silently overwrites local work. The feature is unavailable when the teacher disables resuming. Offline clocks and self-entered codes do not authenticate identity; expiry policies still apply. Analytics may show an in_progress checkpoint as pending, but it is not a final submission or grade. After transferring an attempt, continue only on the destination device: two independently edited copies are not automatically merged. If you close a device without exporting updated progress, only your latest saved checkpoint can be transferred.

7. Result and P2LRN Analytics

Upon completion, the learner downloads a file .p2lrn-result. That file can be:

  • Open directly in P2LRN Analytics using Open results to select one or multiple files.
  • Open from Studio with Review delivery and, from that review, press Open in Analytics.

The learner must deliver the downloaded file to the teacher by USB, email or another authorized method: downloading never sends it automatically. The teacher may import several results without a database or host a protected static index for src. See the CDN and NPM guides.

Analytics transforms the return into a view of learner, course, attempt, activity, openings and sessions. Scores from an offline submission are displayed as informational; They do not automatically become an official grade in an LMS or other academic system.

8. Review a return in Studio

  1. Open the original course.
  2. Click Review delivery and select the .p2lrn-result.
  3. If you kept a receipt from the teacher, select it to compare the assignment.
  4. Review learner, attempt, openings, first and last opening, expiration, sessions, active time, responses, scores and incidents.
  5. If you want to explore the activity in the full dashboard, tap Open in Analytics.

9. Assignment signature and provenance

Studio allows you to sign the conditions of the assignment and save a separate receipt for the teacher. This verification helps confirm that the return corresponds to the assignment that the teacher created.

It should not be confused with the identity of the learner or the origin of the executable that Windows receives. When faced with any executable file, the rule for the learner remains the same: open it only if you know who sent it to you and expected to receive it.

11. If Windows displays a warning

Don't disable SmartScreen, antivirus, or other protections to open a file you don't recognize. First confirm with the teacher or center that the file name, delivery channel and course are as expected. On managed devices, follow facility policies or consult the person responsible for the device.
